## 2 P2 发现（口径与一致性）

### P2-1 `W785 §4.1c` 单位写错（MiB 当 GB 用）

实测 `ram_used` 为 46,989 MiB 与 64,968 MiB（metrics 以字节给出，脚本除以 1048576）。文中写成 "46.9 到 64.9 GB"，
**数值对、单位错**：正确表述是 **45.9 GiB 到 63.4 GiB**；`MemAvailable` 83,676,128 kB 与 65,026,192 kB 即 **79.8 GiB 到 62.0 GiB**。
差 7%（GiB 与 GB 的比值），在"有没有内存余量"这种判断上足以改变结论方向。

### P2-2 `W785` 写 "22.84 GiB"，实为 22.3 GiB

`/metrics` 的 `expert_cache_mib = 22841` => 22.3 GiB（22841/1024）。22.84 是除以 1000 得来的。

### P2-3 `816 B/cell` 与代码算术不一致

`--help` 与 `layer.hpp:222` 都写 816 B/cell；但按 `kv_pool_bytes` 的 hybrid 分支与 scale 为 half 计算：
`2 x (256 + 8x2 + 144) = 832 B`。差 2%。**结论不影响 kv-grow 的"不可达"判定**（那条走的是 VMM，不是容量），
但它影响"K/V 到底占多少"的直觉，应改为"816（文档）/ 832（按代码算术），以运行期为准"。

### P2-4 `MEMORY §2` 曾写"槽 9761 -> 9901"，而 P78/W777 是 9732 -> 9901

9761 是 0.1.47 时代的缓存槽，9732 是 0.1.48.1 未开 HC_Q8 时的值（9901-9732=169，与"+169"自洽）。归属写错，已改。

### P2-5 `verify` 的 PASS 29 -> 28 需要解释，且 `P65` 已成惰性项

- 缺失的那一项就是 `P66 --resident-experts` 本身（配置行消失），**不是隐性失败**：FAIL 仍为 0。
- 但 `P65 STRATA_RESIDENT_HEADROOM_GIB 0.5` 仍被 verify 当有效项断言。该 env 只被 resident 逻辑读取，
  现在**没有 resident 就没有读者**，属"配着但无效"，应标注惰性（本轮在 register 注明，未删，避免无谓变更）。

### P2-6 门行号引的是旧版（`generate.cpp:5154` 实为 `5202-5209`）

`W776:154` 与 `W784:167` 都引 `generate.cpp:5154`，但 0.2.4.2 的源码里 5154 行是 `stage_of(pr.first)` 那段多卡分支，

**处理**：W776:154 行号已更正并注明版本；今后引行号一律带"版本 + 函数名"，不只给行号。

## 5 举一反三：把这次的坑变成规则

### 规则 A：引用门必须引**完整谓词**
上一轮栽在"只引 `!resident_cpu_experts`，漏 `vmm_available()`"。今后任何"某开关能开"的断言，必须：
1. 贴出**整条** `on = ...` 表达式；
2. 逐个谓词标"满足/不满足"；
3. 并在运行期用**引擎自己打印的 off 原因**复核（`--kv-grow is off (...)` 这种日志比读源码更硬）。

### 规则 B：内核优化前先证"这个内核在跑"
`gr_up75_kernel` 的 72-88 B 溢出是死代码属性（`up75_on()` 在 HIP 下 return false）。今后顺序固定为：
**符号存在（反汇编/objdump） -> 在 dispatch 路径上（源码） -> 资源数（ELF 元数据） -> 才谈优化**。
只做后两步就会优化死代码。

### 规则 C：decode 指标必须带混淆因子
`decode_tps` 会因 spec 接受率随文本变化而 ±10%。任何 decode 结论必须同时给：
**接受率、runs 数（>=10 或交错 A/B）、以及阶段 ms（`STRATA_DECODE_TIMING=1`）**。
5 runs 的 tok/s 中位数只能用于"有没有 2 倍级差异"的初筛。

### 规则 D：单位写成"数值 + 单位 + 来源"
`metrics` 的 `*_mib` 一律按 MiB；`/proc/meminfo` 是 kB；文档里出现 GiB 时必须能回算。
本轮 P2-1/P2-2 就是这么来的（同一段里混用三个基准）。

### 规则 E：结论被推翻时，原文加 banner，而不是只在新文档里写
W783/W784 的问题不是"结论错"，而是"错了没回收"。今后凡结论被后续轮次推翻，**原文件顶部加一行勘误并指向新文件**。
