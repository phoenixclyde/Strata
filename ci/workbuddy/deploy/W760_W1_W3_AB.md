## 3 机制（为什么 B 更快 -- 不是"每步更快"）

**B 的 `ms/step` 反而更慢**（74.28 对 72.54），但 **tok/s 更高**。差别全在**草稿接受**：

- A/A2：`220/236`（= `drafts_accepted`），steps = `320-220` = **100**
- B/B2：`223/239` 与 `228/242`，steps = **97 / 92**

-> `tok/s = 每步净出 / 每步耗时`（W748 的分解式）：
**B 每步净出更高**（3.30 / 3.48 对 3.20），代价是每步稍慢。

-> **机制解释**：`--mtp-window 8192` 让**草稿层只关注最近 8192 个 cell**（默认 32,768）-> 草稿更贴合近期上下文 -> **接受率提高**。
这与上游 `STRIX_HALO.md:126` 给的 **+3.5%** 方向与量级都一致（我们 **+3.39%**）。

**顶层的预填不受影响**：6 臂 `prompt_ms` 全在 137,970~138,831（差 0.6%），冷发全是 `pt=64064`、`reused=0`。

## 4 答案核验（按 index 跨臂对齐 -- 同 index 才可比）

| index | 判定 | 各臂 sha16 |
|---|---|---|
| **COLD**（首次、`reused=0`） | **全 SAME** | 六臂都是 `66f879c7` |
| WARM1 | DIFF | A/A2/C/C2 = `603998b4`；**B/B2 = `66f879c7`（= COLD）** |
| WARM2 | DIFF | A/A2/C/C2 = `74817322`；**B/B2 = `66f879c7`** |
| WARM3 | **全 SAME** | 六臂都是 `66f879c7` |
| WARM4 | DIFF | **B2 = `74817322`**；其余 = `66f879c7` |

**怎么判**：**首次（COLD，无会话影响）六臂完全一致** -> **本参数不改首次答案**。
WARM 期的分歧要**与"会话态递进"区分**：基准组 **A 自己也在震荡**（WARM1 `603998b4` -> WARM3 `66f879c7`），
说明那批差异是 **W739 已知的会话态效应**，**不是 `--mtp-window` 引入的**（若真是它引入，B 应系统性偏离 A，而不是"B 恒定、A 在变"）。

-> **判定：不构成"改答案"一票否决**；但**如实登记**这一现象（WARM 期 B 组保持首答、A/C 组发生会话态递进）。

## 6 局限（照实写）

- **单次 6 臂**（每臂型 n=2）；**B 组的臂内差 3.0%**（7122.9 vs 6911.2），比 A 组（0.30%）大 -> **+3.39% 是中位估计**，真值可能在 +1%~+3.4% 之间。
- 只测 **64K 一个长度**；上游说该开关在 **32K 是 -0.4%** -> **长上下文才赚**，短上下文是否略亏**未测**。
- `--mtp-window` 在**预填**上没有可见影响（6 臂 prompt_ms 差 0.6%，在噪声内）。
- 只测**单卡、单并发、单用户**。
