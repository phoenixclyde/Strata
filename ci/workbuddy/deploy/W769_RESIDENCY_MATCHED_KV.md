# W769 驻留匹配的 `--kv` 对照

**结论：分布门（KLD）在本卡上被「专家驻留布局」主导，原理上无法单独裁决 `--kv`。**
`--kv` 确有独立效应（下界 KL 增量 0.14 / argmax 再降约 9 个百分点），但它与驻留伪影**同量级**，
而后者**不可消除**（见 §7）。要判「要不要动 `--kv`」只剩任务级门一条路。

- 日期：2026-10-10 21:34:46 发车 / 21:49:26 收车
- 位置：166 测试台，`1 x MI50 32GB (gfx906)`，引擎 0.1.41 / `strata-gfx906:0.1.41`
- 性能口径声明：`Z0=off`（`--showperflevel` = auto，无人工 cap）
- 4 臂，每臂 1 冷 + 4 温；语料与**被评分位置与 W767/W768 完全相同**
  （`ONLY=tier1_tail0,tier2_tail0`，n=808 配对位置）=> 三车的 KL 可直接对读
- 全部 `--expert-cache auto`（与生产一致）

## 1 为什么做这车

W768 把 W767 的因果归因否掉了：一个纯容量旋钮（同 `--kv`、只改 `--expert-cache` 6000 -> 9000）
就能把分布推 KL 0.366，与 `--kv` 的效应同量级。但 W768 **没有一对是「驻留严格相等」的**
（`rf6` 与 `rc6` 的 N 同为 6000，可 fp16 的 KV 多占显存，实测槽位仍差 489）。所以 W768 只能证明
「有混杂」，回答不了「配平之后 `--kv` 还剩多少」。

### 可控点的来源（源码，不是猜）

`include/strata/plan/plan.hpp:144`：

```
p.cache_bytes = pool - p.kv_bytes - fixed;               // cache_slots = cache_bytes / expert_blob
p.kv_bytes    = kv_bytes_per_token(g) * max_context;     // :134
```

=> **专家槽位由 KV 占走多少直接决定**：KV 少 => 槽位多。所以「让两臂槽位相等」有确定控制量：
把 fp16 的 `--max-context` 缩小，把多占的 KV 让回去。

dtype 的每 cell 字节（源码实读）：`kv_q8.hpp:3-8` 给出 fp16 = 2 x 12,288 B/token（12 个 QSA 层）、
int8 = 12,672；`kv_q4.hpp:4-5` 给出 q4_0 = 576 B/cell vs int8 的 1,056。
（`k8v4` 的实现字节数源码里没有直接常量，所以不猜它，改用实测响应反推。）

已知实测点（W767，`--max-context 262144`）：fp16 `f16a`/`f16b` = **8047 / 8047**（两次完全一致）；
k8v4 `k84` = **9761**。fp16 多占 1714 槽 => 要把那部分 KV 让回去，`--max-context` 估在 120k..131k。

## 3 四臂实测槽位：三点精确共线

| 臂 | `--kv` | `--max-context` | 实测 slots | vs `k262` |
|---|---|---|---|---|
| `k262` | k8v4 | 262144 | **9761** | 基线 |
| `p131` | fp16 | 131072 | **9598** | -163 |
| `p122` | fp16 | 122880 | **9696** | -65 |
| `p114` | fp16 | 114688 | **9794** | **+33（最接近，但不等）** |

三点斜率 = `(9794-9598)/(114688-131072)` = **-0.011963 slots/token**。

解 `slots == 9761` 的落点（三点各自独立外推）：

| 由哪一点外推 | MC* |
|---|---|
| 114688（9794） | 117446 |
| 122880（9696） | 117446 |
| 131072（9598） | 117447 |

**三点独立外推一致到 1 token 以内 => KV 占量与 `--max-context` 在实测范围内是严格线性，
`MC* = 117446` 可作下一车的落点。**

**但本车没能做出「零槽差」的对照**：最接近的 `p114` 仍差 **+33 槽**。

## 4 决定性结果：同 dtype、只差驻留，KL 已经是 0.28-0.30

三个 fp16 臂**只差 `--max-context`** => 只差 cache 能装多少槽 => 只差**被缓存的专家集合**。
fp16 的 KV 是**无损**的，且所有被评分位置（24000..27000、38000..40000）都远在各臂窗口内，
**所以三个 fp16 臂评分的是同一批 cell、同一精度。它们之间的任何 KL 都是纯驻留伪影。**

| 比较 | 槽差 | KL mean | KL med | argmax | top10 |
|---|---|---|---|---|---|
| W767 `f16a` vs `f16b`（同样一切） | **0** | **0.00000** | 0.00000 | **100.00%** | 100% |
| **W767 `f16a` vs W768 `rf6`**（**同 dtype 同 MC**，只差 cache 组成） | **96** | **0.28370** | 0.02901 | 91.46% | 86.89% |
| W769 fp16 `p131` vs `p122` | 98 | 0.28731 | 0.03116 | 89.23% | 86.25% |
| W769 fp16 `p122` vs `p114` | 98 | 0.30449 | 0.02322 | 90.84% | 86.11% |
| W769 fp16 `p131` vs `p114` | 196 | 0.28639 | 0.03405 | 90.47% | 85.99% |
| W768 `rc9` vs `rc6`（同 dtype **同 `--kv`**，容量旋钮） | 1224 | 0.36554 | 0.03065 | 87.38% | 83.37% |

**两件事同时成立，都重要**：

1. **槽差为 0 时 KL 恰好是 0**（两处独立验证）=> 这条路径逐位确定，读数下限是 0。
2. **槽差一旦不为 0，KL 立刻跳到 0.28-0.37 的平台，而且几乎不再随槽数增长**
   （96 槽 0.284、98 槽 0.287、196 槽 0.286、1224 槽 0.366；槽数差 12 倍，KL 只涨 29%）。

其中 **`f16a` vs `rf6` 那一行是最干净的证据**：同 dtype、同 `--max-context`、同评分位置、
同精度，唯一差别是 `--expert-cache auto`(8047) 与 `6000`(8143) 造成 **96 槽**的驻留差
=> **KL 0.284 / argmax 91.5%**。

## 5 `--kv` 的净效应：用上界推下界

| 量 | 值 |
|---|---|
| 最接近配平的一臂 `p114` 的槽差 | **+33** |
| 同 dtype、槽差 **96** 的纯驻留伪影（`f16a` vs `rf6`） | **0.28370** |
| 因 KL 随槽差**不减**，33 槽的伪影必 `<=` 96 槽的伪影 | `<= 0.28370` |
| `k262` vs `p114` 实测 | **0.42770** |
| **=> `--kv` 的净 KL 增量** | **`>= 0.14340`** |
| 同理 `k262` vs `p122`（槽差 65） | 0.41558 => 净增量 `>= 0.13188` |
| 独立核对（W767 路线）：`k84` vs `f16a`（1714 槽，**方向须与 W767 一致 = `KL(f16a || k84)`**）**0.40416** 减去 1224 槽伪影 0.36554 | 净增量约 **0.039**（原写 0.48406/0.119 系方向取反，**W773 更正**） |

**三条估计（W773 更正后）**：同车同参考的两条 **0.14340 / 0.13188** 一致；**跨车那条只有 `0.039`** （原 0.119 系把 `KL(k84 || f16a)` 误当 `KL(f16a || k84)` 用，方向与 W767 相反）。=> **不再称"三条一致"**：同车路线给 `>= 0.1434`，跨车路线给 `0.039`，**两者相差 3.7 倍**。这本身又一次说明：**这个门量不出 `--kv`**（两种"减去驻留伪影"的减法给出不同答案，因为伪影是**阶跃饱和**的、不可线性相减，见 §4 与 W767 §8）。
按 argmax 口径更直观：纯驻留把 argmax 从 100% 压到约 89-91%，`--kv` 再压到 80.7-84.4%。

**=> `--kv` 的效应真实存在，且不能由驻留解释。但它是次级项。**

## 6 机理：命中与未命中走不同代码路径

引擎对 **cache 命中**的专家与**未命中**的专家走两条不同路径（引擎启动日志：
`R4 hit path ON`、`token graph hit path`）。当某个 token 路由到的专家「在不在 cache 里」翻转时，
该 token 的合并就走另一条路径、另一套累加顺序 => 引入**固定量级**的数值扰动。

这解释了为什么 KL 是**阶跃**而不是线性：**扰动的大小由「翻转的 token 数」决定，而不是由「槽数差多少」决定。**
96 槽差足以让边界上一批专家的驻留状态翻转；再涨到 1224 槽，翻转的只是更多的边界专家，量级不变。

=> 由此得到一个**重要的推论**：`--kv` 的定义就是改变 KV 占量，而 KV 占量必然改变 cache 能装多少槽，
=> **`--kv` 与「驻留布局」在本引擎上原理上不可分离**：任何 `--kv` 的 A/B 都必然同时改变驻留，
而驻留本身就带 0.28-0.37 的底。

## 7 结论

1. **分布门无法单独裁决 `--kv`**。它测到的首先是「专家驻留布局」；`--kv` 的信号（净增量 0.12-0.14）
   与驻留伪影（0.28-0.37）同量级，且后者不可消除。**「驻留严格相等」这个条件在本引擎上不可达**，
   因为让两臂驻留相等就得让 KV 占量相等，而 KV 占量正是被 A/B 的那个量本身。
2. **`--kv` 确有独立效应**（真实，非零，下界 0.12-0.14 KL / 约 9 个百分点的 argmax）。
   所以「生产用 `k8v4` 与 fp16 分布相同」**不能**由本车支持；但「分布不同就意味着质量更差」**同样不能**支持
   （W767 已证四个标量互相矛盾：PPL 反降、自身 top1 命中反升、停止质量反降）。
3. **要判「要不要动 `--kv`」只剩任务级门**：needle / 配对 McNemar。它不问分布像不像，
   只问任务做得对不对，对这类扰动天然不敏感 -- 而这正是决策需要的口径。
4. **槽位是可靠的控制量**（跨车精确复现 9761，三点共线到 1 token）=> 若将来要做任何
   「控制驻留」的实验，`slots == 常数` 可以直接用，`MC* = 117446` 是 fp16 对 `k8v4@262144` 的理论落点。
5. **一条可复用的方法学判据**：**凡用分布类指标做 A/B，必须先做一组「同 dtype、同精度、只差
   非目标旋钮」的对照**。本车正是靠这一组（B 组）才发现门被驻留主导 -- 若只做 `k262` vs `p114`
   就会得到「KL 0.43，差异巨大」的错误结论。

## 8 局限（照实写）

- **没有做出零槽差的对照**：最接近的 `p114` 仍差 +33 槽。「`--kv` 在零槽差下还剩多少」没有直接测量，
  §5 的下界是用「伪影随槽差不减」推的，不是实测。
- **fp16 三臂各自的 KV 长度不同**（131072 / 122880 / 114688），虽然评分位置都在窗口内、
  fp16 无损，但**没有独立验证**三臂在被评分位置上的 KV 内容逐位相同（未插桩）。
- **`--max-context` 与 cache 槽位的线性关系仅在 114688..131072 区间实测三点**，
  外推到 117446 是一小步（区间内），但更远处未验。
- 单卡、单 pack、单语料、n=808 配对位置；未做多语料重复。
- 本车**只测分布，不测质量**；本报告不含任何「哪个 `--kv` 更好」的结论。
