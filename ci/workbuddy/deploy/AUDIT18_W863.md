## P0

### A1 R23 的「+4.0%」不达新判据 —— 结论需要降级

| 项 | 值 |
|---|---|
| 原始数据 | `166:w863/ab_20261101_144755.txt`（四臂交错，每臂 3×480 tok） |
| ARM T（R 表） | 47.0 / 48.4 / 48.8 / 47.6 / 49.8 / 50.2 → median **48.60**，CV **2.32%** |
| ARM B（R=1） | 44.7 / 46.4 / 47.1 / 45.8 / 49.1 / 48.1 → median **46.75**，CV **3.09%** |
| 中位差 | **+3.96%** |
| 判据 2×CV | max = **6.18%**，pooled = **5.41%** |

**3.96% < 5.41%** ⇒ 按本仓刚立的判据（`MEMORY §1`：2 倍 CV），这个幅度**不成立**。

我之前的表述是「+4.0% 高于 2.12% 阈值，方向可信」——那个 2.12% 来自**另一次** bench（CV 1.06%），
拿别的 run 的 CV 去判这一次，是错的。**同一批数据、正确口径，结论是「噪声内」。**

能保留的：
- 两轮配对**同向**（+4.31% / +3.53%），方向一致；
- 独立微基准 `q8_group_bench` 在 ncols=2 上是 **1.156×**（261.2 → 226.0 µs），机理清楚。

⇒ 正确表述：**方向可信（配对同向 + 微基准支持），幅度不可信（< 2×CV）**。
要证实幅度，须按新方法重做（n≥12、丢 2 发、交错），代价约 20 分钟停服。**暂不做**：
R 表逐位等价、无害，且微基准已证明内核本身快了。

**处置**：`deploy/W863_R23_DEPLOY.md` 顶部加降级横幅；账本 R23 的 note 同步。

### A3 记忆里的 env 口径混淆 —— 已经害我误判过一次

`MEMORY §2` 写 `env(12): HC_Q8·PROMPT_F16·ROCBLAS·ATTN_SWIZZLE·SELECT_SIMT·GDN_HEAD+PP2·RT_SKIP=7·CPU_SHARE=…`
但生产 config 的 `env` **只有 6 项**，且其中**没有** `HC_Q8` / `PROMPT_F16` / `ATTN_SWIZZLE` / `SELECT_SIMT` / `GDN_PP` / `RT_SKIP`。

真相：这 6 个是 `STRATA_GFX906_TUNED=1` 在 `arch_defaults.cpp:222` 用 `setenv(...,0)` **进程内注入**的，
不在 config 里。`env(12)` 是「有效 env」，不是「config 里的 env」。

**后果已经发生**：我在 HC 探测那轮看到 config 只有 6 项，据此判断「HC_Q8 默认关、走 bf16」，
方向判断错了整整一轮，靠日志横幅才纠正。

**处置**：`MEMORY §2` 改成两行分别写「config env(6)」与「tuned 注入 6 项」。
