# 方案推进量化（滚动快照）

> 唯一分母：`deploy/PROGRESS.tsv`。每轮报"共多少 / 已做多少 / 本轮多少"只从这里算，不凭印象。
> 生成命令：`python albus/w863/plan_stats.py`（按 block 拆：见 §3）。

## 1 口径（先定清楚，否则数字会骗人）

| 符号 | 含义 |
|---|---|
| **总数** | `count` 的加权和。不是行数——B3 的「28 个 HIP 死块」是一条记录、权重 28 |
| **已结** | `done` 的加权和。状态 ∈ {DONE, DONE_NEG, NA} 时 `done` 必须等于 `count`（本轮修过 3 处不一致） |
| **完成率** | 已结 ÷ 总数 |
| **采纳率** | DONE ÷ 已结。**判否也是成果**，所以分母是"已结"而不是"总数" |
| **本轮 +/−** | 本轮结清的条数 / 本轮新开的条数 |

两个口径必须都报，因为 B3 那个池会显著改变观感：

- **全量**：113 条（含 28 个死块）
- **剔除死块池**：85 条（死块是同一套方法的 28 次重复，不该按"28 个决策"计）

| R23 R 表实测版 | 内核改动 | **decode +4.0%**（同镜像 A/B，48.6 vs 46.8 tok/s） | **已上线**（0.1.55h） |

| R25 HC 探测 | 探针 | **无信号**（±30% 噪声内） | 结清，换来"非带宽受限"的结论 |

**累计已上线墙钟收益 = +4.0%**（R23 是唯一一条上线的性能改动；其余 DONE 多是结论/探针/环境）。
不给"相加的累计值"——没有统一的基线，相加会骗人。
