## 1 指令层实测（当前生产引擎 0.1.56 / v0.2.10）

口径同 W909：`llvm-objcopy --dump-section=.hip_fatbin` → carve 出 68 个 gfx906 code object → `llvm-objdump -d`。

| 指令 | **0.1.56**（现在） | 0.1.55（W909 当时） | Δ |
|---|---|---|---|
| **`v_dot4_i32_i8`** | **146,604** | 130,808 | **+12.1%** |
| **`v_dot8_i32_i4`** | **0** | 0 | — |
| `v_dot4_u32_u8` | 0 | 0 | — |
| `v_dot8_u32_u4` | 0 | 0 | — |
| `v_fmac_f32` | 122,684 | 72,017 | +70% |
| `v_mul_lo_u32` | 32,980 | 32,959 | ≈0 |
| `ds_read_b128` | 19,044 | 7,344 | +159% |
| 总静态指令 / 内核 | 3,782,033 / 3,290 | 3,492,465 / 3,145 | +8.3% / +4.6% |

**dot4 是现役指令**：14.6 万条，遍布 MMQ 与 attention 的 DDA 路径。**「移植 dot4」这个动作不存在** —— 除非指「在某个新内核里第一次用它」，而我们的新内核（`qsa_*`、`native_mmvq`、`multicast`）本来就是用它的。

**dot8 一条都没有。** 源码侧同样：

```
grep -rl  sdot8 / __builtin_amdgcn_sdot8 / v_dot8   strata=0 files, llama.cpp=0 files
         sdot4                                       strata=2 files, llama.cpp=1 file
         __dp4a / ggml_cuda_dp4a                     strata=15,      llama.cpp=3
         dot8（命中 4 个文件）                         是 FP32 辅助函数名 dot8/dot8u，不是指令（W909 已核）
```

## 2 为什么 dot4 不用"移植"，dot8 也不用"整体移植"

dot4 的问题从来不是「有没有」，而是**供给率**：同卡实测上限 21.52 TMAC/s，生产折算 4.55 = **21%**。W924 的 ISA 计数给出了原因结构（Q4_K 实例：dp4a 5,184 条，解包 1,437 / LDS 1,204 / 缩放 1,064 / 地址 824）。

dot8 的收益不来自「指令更快」这一句，而来自三个耦合条件 —— 这就是我 W909 判错、W927 纠正的那件事：

| 条件 | Q4_K（gate/up，20.4% of prefill） | Q5_1 / Q8_0（down，13.8%） |
|---|---|---|
| 权重位宽能被 dot8 吃（i4×i4） | ✅ u4 用 `^0x88888888` + 修正项 `8·sum(x)`，W927 同卡三路互证 **ALL MATCH** | ❌ 5-bit / 8-bit，塞不进 |
| 激活必须也是 int4（W4A4） | ⚠️ 现在是 Q8_1(int8) ⇒ **必须降位宽**，这是精度决策 | — |
| 覆盖到的 prefill 份额 | 20.4% | 0 |

⇒ 端到端上限（W928 修正后）= **3.22%**，正好压在噪声门 3.2% 上。

## 3 方案里的缺口：只有「验证」和「门」，没有「实现」

翻 `W832 §6.5` 与 `PROGRESS.tsv`，与 dot8 相关的只有两条：

| ID | 内容 | 状态 |
|---|---|---|
| R73 | `v_dot8` 用于 Q4_K 的**正确性 + 吞吐**验证（三路互证、49.66 TMAC/s） | DONE |
| R74 | **W4A4 精度门**（int4 激活的 KL / top-1） | OPEN |

**「把 dot8 接进 MMQ 内核」这件事没有任何条目。** 这就是审计该抓出来的东西：验证做了、门槛列了，中间那一步凭空消失了。

⇒ 新增 **R84**（依赖 R74）：

| 项 | 内容 |
|---|---|
| 范围 | **仅 gate/up 的 Q4_K 实例**；down（Q5_1/Q8_0）保持 dp4a —— dot8 是 i4×i4，Q5_1 是 5-bit |
| 改动点 | `vecdotq.cuh` 的 `vec_dot_q4_K_q8_1_impl_mmq` 增加 int4 分支：权重 `^0x88888888`，加修正项 `8·Σx`；激活量化器从 Q8_1 换成 int4 打包 |
| 前置 | R74 的 KL ≤ 0.005（分辨率 0.0032）|
| 路径断言 | ISA 里 `v_dot4_i32_i8` 在 Q4_K 实例内应减半、并出现 `v_dot8_i32_i4`（>0）—— 这是"确实执行到"的硬证据 |
| 通过判据 | prefill `|Δ| ≥ 2×CV`；端到端上限 3.22%，**不预设** |
| 风险 | int4 激活改求和序 ⇒ 必须过 KL；`v_dot8` 要求 8 元素对齐（ncols % 8 == 0）|

## 5 本轮事故：`objcopy` 原地重写了生产二进制

为取 0.1.56 的 fatbin，我执行了：

```bash
llvm-objcopy --dump-section=.hip_fatbin=fat156.bin /data/bin/strata-0.1.56
```

**`objcopy` 在只给输入、不给 `-o` 时，会把结果写回输入文件。** 后果：

```
修前： running ae085365 (42,924,432)  |  disk 7afc2bbf (42,898,432)  ← 被改小 26 KB
       /proc/20/exe -> /data/bin/strata-0.1.56 (deleted)
```

进程还持着旧 inode，服务没受影响（`/health ok`、restarts=0），但**磁盘件已经不是被审计、被记账的那一个** —— 下次重启会静默换成一个未验证的 ELF。

**已修**：`docker cp build-r28/strata → .new` + `mv`（换 inode），三方复核 `disk = build = running = ae085365`。

**纪律 ⑯（新增）**：**任何分析工具对生产二进制必须只读** —— 先 `cp` 到 /tmp 再处理，或显式 `-o 新文件`。禁止把 `/data/bin/*` 直接当 `objcopy`/`strip`/`dsymutil` 的输入。同类工具：`patchelf`、`llvm-strip`、`install_name_tool`。

**它同时验证了报告标准第 8 项的价值**：`disk ≠ running` 这一行如果每轮都写，这类污染当场就能看见。
