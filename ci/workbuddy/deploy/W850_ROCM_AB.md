- 方向明确：**10.1 的 prefill/read 全面更慢**，小 prompt 最差（2575 tok +11.5%）；decode 差异落在 A 自身离散（44.67–46.10）里，**算中性**。

## 2 归因：不是"ROCm 变慢"，是**我们的 rocBLAS 表被版本检查挡掉了**

B 臂启动日志（原文）：

```
prefill gemm: rocBLAS version mismatch: file=5.5.0.cd957402309 runtime=5.7.0.962d0059
              (/data/gfx906-rocblas-5.5.0.txt); rocBLAS's default kernels run
```

A/A2 臂则是：

```
prefill gemm: rocBLAS tuning enabled (56 rows, 47 with a solution, gfx906, rocBLAS 5.5.0.cd957402309)
```

即 10.1 的 rocBLAS 是 **5.7.0.962d0059**，与表头的 `5.5.0.cd957402309` 不匹配，引擎**主动拒绝**并用 rocBLAS 默认解。
这正是赛前预料到的混淆项 —— 所以本实验的结论只能写到这一步：

> **"10.1 + 没有可用表"比 "7.14 + 有表" 慢 3.4–11.5%（read）。**

而表本身的价值有历史实测：**瘦 N 桶 `320x10240` 1.27×**（P107/P108）。小 prompt 恰恰是最瘦的 N ⇒ +11.5% 与"丢了表"高度一致。

## 3 判词

**不采纳 10.1（as-is）。** 理由不是"10.1 一定差"，而是：

1. 采用它必须**先重 tune** 一张 5.7 的表（`tools/hip` 的 tuner，历史同类校准约 55 min），否则立刻倒退 3–11%；
2. 而 10.1 相对 7.14 的**预期收益本来就没有证据**：ROCm 10.1 的发布重点是数据搬运（hipFILE / Infinity Storage 异步快路、批量 I/O）与 NUMA 感知的主机内存分配、ROCm CLI，
   这些 Strata 一条都没用到（我们只吃 HIP 运行时 + rocBLAS）；
3. 官方 10.1 兼容矩阵**仍不含 gfx906**，能跑是因为我们自己的 TheRock 构建 ⇒ 没有上游保证。

⇒ 记为 **REJECTED（as-is）**；**重新评估的前置条件是"先做出 5.7 的 rocBLAS 表"**，否则任何对比都是"表 vs 无表"。
候选镜像 `strata-gfx906:0.2.9r1`（15.07 GB）保留作证据，不删。

## 4 顺带核实：ROCm 10.1 会移除 rocm-smi，会不会打坏我们的遥测？

上网查到的 10.1 变更里有一条"ROCm SMI removed, migrate to amd-smi"。我们的遥测是**自写补丁**，所以专门查了：

| 检查 | 结果 |
|---|---|
| `serve/telemetry.py` 是否 shell 调用 rocm-smi | **没有**（全库只有 `src/program/generate.cpp:4585` 的一句提示文案提到 rocm-smi） |
| 遥测数据来源 | **sysfs**：`/sys/class/drm/renderD<N>/device` 读 `gpu_busy_percent`、`mem_info_vram_used/_total`，`hwmon` 读 `temp1_input`、`power1_average` |
| 两个镜像里 smi 工具 | 7.14 与 10.1 镜像里 `rocm-smi`、`amd-smi`、`rocminfo` **都在** |

⇒ 这条变更对我们**无影响**。这条是为了防止"换 userland 顺手打坏 PCIe/FRU 遥测"而做的定点核对。

## 5 实验成本与脚本缺陷（如实记）

- 三臂用时：A ready 242 s / B 258 s / A2 280 s + 每臂测试约 60 s，**总 21.5 min**；收尾把生产用 0.2.9t2 重新拉起（258 s，门禁 PASS）。
- **脚本命名有 off-by-one**：`arm-<label>` 是 `docker rename` 之前那个容器，所以 `arm-A2` 实际装的是 **B 的容器**（0.2.9r1，Exited 0）。
  **数据不受影响**（每臂读数取自当时正在跑的那个容器），但下次要把 rename 放到建新容器之后，或直接把 label 写进容器 list 注释。
- **另一处采证污染（AUDIT16 P2-21 补记）**：A2 段的日志里混着 B 臂的 `version mismatch` 行——所有臂共写同一个 `/data/strata-huihui-*.log`，而本轮没有用"启动前行数"做 mark。A2 真的是 7.14 靠的是同一段的 `rocm: 7.14` + `56 rows` 两行，以及数值与 A 同形（±0.2%）。下一轮起 mark 成为硬要求（W851 起已执行）。
- 收尾后 `verify_tip.sh` 仍 **TIP-OK**：分支 `gfx906/0.2.9-mi50 @ aef9d256`，`/src` 5319 文件与 HEAD 逐位相同。

## 6 结论一句话

**ROCm 停在 7.14。** 10.1 要能比，得先有一张 5.7 的 rocBLAS 表；在拿到"表后仍更快"的证据前，不值得为它多背 6.9 GB 镜像和一条无上游保证的 userland。
