# W889 · R38 的前提不成立：HC 这条读**不是带宽受限**，限制它的是**占用率随窗口 T 减半**

**结论先行**：R38 写的「生产 97 GB/s vs 探针 260 GB/s = 2.7×」这条比值**不能用**——三个数各有各的问题（§1）。
从**出厂汇编**能读出的事实是：HC down 的 VGPR 随窗口 T 线性上涨（93→119→**140**→160），
而 gfx906 每 SIMD 只有 256 个 VGPR ⇒ **超过 128 就从 2 block/CU 掉到 1 block/CU，占用率 25% → 12.5%**。
生产窗口 T∈{2,3,4}（最近三条 `avg T 2.75 / 3.25 / 2.75`），**T≥3 的那部分正好掉下悬崖**。

> **但占用率不足以解释这件事，先说清（§2.5）**：HC **up** 的占用率是 **37.5–50%**，是 down 的 3–4 倍，
> 而它实测 **80 GB/s**（`W862`：HC up 3.48 MB / 43.5 µs），和 down 的 ~98 GB/s **同一条带**。
> ⇒ 占用率翻几倍并没有换来带宽 ⇒ **真正的限制项大概率不是占用率**，而是两个方向共有的东西
> （34 字节 q8 块的取指方式，`W862 §3.3` 已经点名）。`STRATA_TSUM=1` 这次 A/B 的价值就在这里：
> **它让 T=3 的占用率翻倍而计算量不变——如果 hc 不变快，就直接把「占用率」这一嫌疑排除掉。**

## 1 R38 的三个数字，逐个过一遍

| R38 原文 | 问题 |
|---|---|
| 「生产 **97 GB/s**」 | `W863` §167 已自认：「之前我把『hc 6.89 ms』当精确值去推 97 GB/s、慢 2.5 倍，那是**用一个噪声 ±30% 的量算出来的比值**」。同配置 hc 实测在 **5.34–8.61 ms** 之间跳 |
| 「探针 rep=1 的 **260 GB/s**」 | 探针是**不同形态**（不同 T、不同权重布局）的合成读。而 `W863` 已经给出一条更硬的对照：**字节翻倍（Q8 644 MiB → bf16 1.28 GiB）几乎不改变 hc 的时间** ⇒ **这条读不是带宽受限**。既然不是带宽受限，拿 GB/s 比值当「可挖倍数」就是量错了东西 |
| 「**119 VGPR**（25% 占用率）」 | 119 是 **T=2** 的实例。生产窗口是 T∈{2,3,4}，**T=3 是 140 VGPR、T=4 是 160**，都掉到 **12.5%**（§2） |

⇒ R38 不该写「2.7× 可挖」，应写成：**「HC 占窗口 15.3%，且它的每 token 成本随 T 上升」** —— 后者才是能动手的东西。

## 2 从出厂设备汇编读出的占用率（`ci/r33_occ.py`，`ci/state/vgpr/fused_gr.s`）

gfx906 的硬约束：**每 SIMD 256 个 VGPR**，分配粒度 4；block = `THREADS=256` = 4 个 wave64；
占用率 = 每 CU 常驻线程 / 2048。

| 内核 | T=1 | T=2 | **T=3** | **T=4** | T=8 |
|---|---:|---:|---:|---:|---:|
| **down（非 fast，生产用这个）** | 93 VGPR / 25% | 119 / 25% | **140 / 12.5%** | **160 / 12.5%** | 229 / 12.5% |
| down（fast，`STRATA_TSUM=1`） | 93 / 25% | 111 / 25% | **128 / 25%** | 147 / 12.5% | 209 / 12.5% |
| up（非 fast） | 44 / 62.5% | 60 / 50% | 73 / 37.5% | 83 / 37.5% | 123 / 25% |
| LDS/block | 2,592 B | 5,184 B | 7,776 B | 10,368 B | 20,736 B |

**悬崖在 VGPR = 128**（= 256 / 2 wavesperSIMD）：只要 ceil4(vgpr) ≤ 128，每 SIMD 能驻 2 个 wave、每 CU 8 个 wave
= 2 个 block；一旦到 132 以上就只剩 1 个 block。**生产非 fast 在 T=3 是 140 —— 超出悬崖 12 个 VGPR。**

## 2.5 反证：占用率不是唯一解释项（我自己这条结论的边界）

| 内核 | 占用率 | 实测带宽 | 出处 |
|---|---:|---:|---|
| HC **down** | 12.5%（T≥3）/ 25%（T=2） | ~98 GB/s（相位表推算，噪声 ±30%） | 本文件 §2 |
| HC **up** | **37.5%（T=3–4）/ 50%（T=2）/ 62.5%（T=1）** | **80 GB/s**（3.48 MB / 43.5 µs） | `W862 §3` 表 |

**占用率差 3–4 倍，带宽只差 20% 而且方向相反（up 更低）** ⇒ 占用率不解释这条带。
两个方向共有的东西是：**q8 权重按 34 字节块存，`qs` 落在 +2，每 8 字节要 4 次 u16 载入**（`W862 §3.3` 逐字）。
所以正确的下一步不是「提占用率」，而是**先把这两者分开**——`STRATA_TSUM=1` 恰好是一个天然的分离器（见 §4）。

## 3 为什么 VGPR 随 T 涨：T 循环被完全展开，每个 T 一个累加器

`fused_gr.cu:2278` 一带（`gr_down_q8_kernel<T>`）：

```cpp
#pragma unroll
for (int k = 0; k < T; ++k) {          // ← 完全展开：T 份寄存器同时活着
    #pragma unroll
    for (int s = 0; s < 3; ++s) { ... acc[k] = fmaf(...); }
}
const float mine = tsum<P>(acc, lane);  // ← 最后才归约
```

`acc[T]` 加展开的中间量 ⇒ **每多一个 T 大约 +20 VGPR**（93→119→140→160，正好每档 20 上下）。
这不是「代码写得差」，是「为了 ILP 把 T 份累加并行做」的直接代价——**它买到 ILP，付出的是占用率**。

## 4 三个杠杆，按代价排

| # | 动作 | 预期 | 代价 | 风险 |
|---|---|---|---|---|
| **1** | **`STRATA_TSUM=1`**（走 `gr_down_q8_fast_kernel<4>`） | T=3 时 **128 VGPR → 回到 2 block/CU（25%）**；T=4 仍 147（1 block） | **零代码**，一次重启 | **改求和顺序**（不同归约），要过 KL 门；T=4 无收益 |
| **2** | **把 T 循环拆两趟 / `#pragma unroll 1`** | 目标 VGPR ≤128（T≤4 全程），占用率翻倍 | 改内核 + 编译 | 掉 ILP，吞吐可能反而降——**必须 A/B** |
| 3 | 窗口封顶 T≤2 | 稳在 25% | 调参数 | **与 R43 冲突**（T 是白拿的 token），不取 |

**杠杆 1 的意义在于它是零代码的，而且是一个干净的判别实验**：现成的 fast 变体在 **T=3** 恰好压在 128 这条线上
（非 fast 是 140）。**同样的计算量、多一倍的常驻 block** ——
- hc 明显变快（≥30%）⇒ 占用率确实是限制项，接着把 T=4 也压到 128；
- hc **不变**（±5%）⇒ 占用率不是限制项，转 `W862 §3.3` 的指令发射方向（34 字节块取指），
  那条已经有 1.43–1.84× 的实测先例。

它唯一的问题是改变求和顺序（`tsum<P>` 的 P 决定归约形状）⇒ 按本项目的规矩要过 KL 门（`STRATA_LOGPOS`，底噪 0.0024）。

## 5 判据与下一步

**判据（按 P188 的规矩）**：`STRATA_DECODE_TIMING` 的 **`hc` 相位 ms/window**（不是墙钟 tok/s）。

| 项 | 现值 | 目标 |
|---|---|---|
| hc 相位 | 6.89 ms/窗口（噪声带 5.34–8.61） | **≤4.5 ms（−35%）** |
| 旁证 | `avg T`、`tokens/window` 不变 | 不变 |
| 质量门 | — | KL 中位 ≤ 底噪 0.0024（否则不采纳） |

**一次重启打包两件事**：①加 `STRATA_TSUM=1` 量 hc 相位；②同时开 `STRATA_TRACE` 抓同一形状的对比。
若 hc 掉到 4.5 ms 以下且 KL 在底噪内 ⇒ 采纳；否则转杠杆 2（改内核，需 build）。

## 7 一条方法论

R38 是我自己写的条目，它的三个嫌疑里 **②（119 VGPR / 25%）只是 T=2 的快照**，
而 ①（631 KB/块）和 ③（LDS 往返）都建立在「带宽受限」这个前提上——**而这个前提被 `W863` 自己的
「字节翻倍不改时间」否掉了**。
⇒ 教训：**写条目时把「已知的否证」一起抄进去**，否则下一条目会拿被否掉的前提继续推。
这跟 `P23` 停在「值保持 0」、`P105` 停在 5.5.0 表是同一类：**新证据进了最新一篇，旧条目原地不动**。
