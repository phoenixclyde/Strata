## 1 为什么这一轮必须带着表一起换

`prefill gemm` 的表头绑 rocBLAS **完整版本串**（`5.5.0.cd957402309`）。换 ROCm 后若还挂旧表：

```
prefill gemm: rocBLAS version mismatch: file=5.5.0.cd957402309 runtime=5.7.0.962d0059
              (/data/gfx906-rocblas-5.5.0.txt); rocBLAS's default kernels run
```

W850 量到的「10.1 慢 3.4–11.5%」就是这个状态。W851 已用 tuner 在 5.7 上重做了一份 84 行的表，
且证明它与 5.5 的表**逐行判定 0 分歧**。所以这次 A/B 的正确配对是：

- **A**：ROCm 7.14 + `gfx906-rocblas-5.5.0.txt`（56 行）— 原生产
- **B**：ROCm 10.1 + `gfx906-rocblas-5.7.0.txt`（84 行）— 目标态

只换其中一个都会把「表失效」误读成「ROCm 变慢」。

## 6 一个必须记住的限制

镜像的 `/opt/rocm` 是**从本机 `routek-base:gfx906-rocm101-hip716` 拷进来的**（AMD 官方 10.1 矩阵不含 gfx906，
这是社区/TheRock 构建）。这意味着：

- **不要**用官方 `rocm/rocm-terminal:10.1` 之类的基础镜像重建，会丢 gfx906 的 rocBLAS 内核；
- 重建镜像时这两个层都要保留：`COPY --from=rocm101 /opt/rocm /opt/rocm`（先 `rm -rf` 旧的）+ 0.2.9 全树 + 组件包。
