## 3 为什么「好多都回滚了」但计数不掉

```
24 个提交累计      +3515 −56
净差异（v0.2.9..HEAD） +3472 −13
差                43 行（全在 ci/probe/*.cpp 内部改写）
```

被撤回的那几条，撤回的是**结论**，不是代码：

| 撤回项 | 撤回发生在 | 曾进过可执行路径吗 |
|---|---|---|
| R34 / R35（LDS 零冲突、dp4a 归因） | docs + 探针注释 | **没有** |
| R41 / C4（"前缀完全不复用"） | docs（探针形态错了） | **没有** |
| R23（+4.0% 幅度降级） | docs（重算 < 2×CV） | 代码是 R 表，保留 |
| R40（`--prompt-cache-every`） | docs（判否：不在关键路径） | 没有改代码 |
| R42 §11.3（4KB 页） | docs（W864 证伪） | 没有改代码 |

⇒ **这套模式的意义正在这里**：把「假设」先写成探针/文档、"改动"只在被证之后才写，
所以回滚成本是 0 行代码。代价就是 `git log` 越攒越长、看起来像干了很多事——**本轮把它标注清楚**。
