## 0 方法与口径

- 只比**同引擎 + 同 pack + 同形状**的读数：prompt 为固定 85 token 的短句、`max_tokens=400`、贪心、单并发。
- 全部读数取**引擎自报**（`/metrics` 的 totals 与 per-request 表 + 引擎 stderr 的 per-request 摘要）。
- 已知两个混杂量必须控制：**生成长度**决定 MTP 草稿接受率、**冷/温**决定专家命中率。
  => 主判据用 **ms/step**（每次 verify 步的耗时 = `decode_ms / (生成 - 接受)`），它对草稿轨迹不敏感；
  并**只比温发**（`reused>0`），冷发单独标注。

  原因不是参数：**生产容器 Up 53 分钟且专家缓存已按服务过的请求热透**，臂容器是**冷启**。
- 单发噪声量级：生产的 4 条温发 ms/step 40.80~45.06（非单调于 net，散布约 3%）。

## 4 结论

1. **是。当前生产容器（现役配置）就是我们跑过的配置里最快的那一档**，本次两轮实测居首，且**没有任何历史配置超越它**。
2. 差距不来自生产有什么特殊参数（它的 config 与臂逐键相同，只差 `log` + `port`），而来自**容器状态**：
   生产长期在线、专家缓存热透；臂是冷启。这解释了生产在**冷发**上快 30%。
3. 明确更慢的只有 `STRATA_EXPERT_V2=1`（ms/step 45.8 vs 43.4，约 **-5.6%**），与 W739 的结论一致。
   `STRATA_TSUM=1` 速度并列（43.40）但**让输出失去复现性**，已否决。`MTP_SHARED_BRANCH=0` 无差。
4. 因此「自己跟自己比」的答案是：**参数面已收敛，跑过的配置里现役最快**。
   要再快只能靠**没跑过的**方向（`--mtp-window 8192` / `STRATA_SH_STREAM` 等，见 W741 §10 与 register P40-P43）。

## 5 口径警告（引用时必须带）

- **不可跨生成长度比 tok/s**：`gen=64` 的接受率约 0.87、`gen=400` 约 0.80、`gen<=16` 约 0.68 => 短生成有时反而更快。
- **不可跨冷/温比**：新会话首发命中率约 85%、温发约 95%，速度差 1.36 倍（W743）。
- **不可用单次拟合外推**：本波 4~6 个点的线性拟合会出现负斜率（假象），只能用**邻近 net 直接比**或同轨迹比。
- 本波生产实测是**单并发、单用户**；并发吞吐仍是**空白面**。

## 6 顺带更正：生产日志里那 18 条 pt=85 不是生产自有的

- `D:/workbuddy_space/strata_ws/deploy/tmp/_w742_prod_log.txt` 里 18 条 `pt=85 / gen=400` 与 W727 三臂**逐条重合**（decode 与草稿数一致）。

- 后果：**任何引用"生产日志读数"的地方，必须先剔掉那 18 条**（它们是臂的，跑在独立端口 8095）。
- 对照：W738 的臂**已**改 `log`（`_w738_ab.out` 第 13 行"造臂 config（只改 log + port）"），所以 W738 波的臂读数**没有**污染生产日志。
