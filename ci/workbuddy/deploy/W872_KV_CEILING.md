# W872 · KV 量化的收益上限被算出来了：长上下文里 KV 读只占 5%

> 2026-11-01 23:22–23:40。**零部署**。这一轮把「KV 要不要换量化」从判断题变成算术题，
> 顺带把 ≥32k 的 decode 变慢指向了**选择器（QSA block scoring）**，而不是 KV。

---

## 0 三句结论

1. **KV 读的绝对量很小**：实测 KV ≈ **17 KB/token**（W871），64k 上下文每生成一个 token 要把整段 KV 读一遍
   = 64k × 17 KB ≈ **1.1 GB**，在 884 GB/s 的实测屋顶下 = **1.24 ms**。
   而 ≥64k 档的实测是 **24.0 ms/token** ⇒ **KV 读只占 ~5%**。`[实测]+[算术]`
2. 所以**任何 KV 侧的量化（8-bit、更激进的 K/V）在长上下文也只能买到 ≤1.2 ms/token**，在 2k 聊天里是 0.04 ms。
   **这条路的天花板就在这里，不必再试。**`[实测]`
3. 真正随上下文涨的是**别的东西**：ms/token 从 2–4k 的 **16.6** 涨到 64–128k 的 **24.0**（+7.4 ms，+45%），
   而 KV 读只解释其中 1.2 ms；注意力 matmul 按 48 层 × 8 KV 头估也只有 ~0.5 ms。
   ⇒ 剩下那 ~6 ms 指向 **QSA 选择器（每步要扫全上下文的 block 打分）**，这才是 ≥32k 的解码瓶颈。`[推测，需一次 A/B]`

## 1 ms/token 随上下文的形状（3567 条 ≥32 token 的回复）

| 上下文 | n | ms/token | tok/s |
|---|---:|---:|---:|
| 0–2k | 798 | 22.13 | 45.2 |
| 2–4k | 65 | **16.61** | **60.2** |
| 4–8k | 294 | 18.61 | 53.7 |
| 8–16k | 96 | 19.65 | 50.9 |
| 16–32k | 301 | 17.20 | 58.1 |
| 32–64k | 381 | 23.12 | 43.3 |
| 64–128k | 1391 | **24.00** | 41.7 |
| 128k+ | 241 | 23.84 | 41.9 |

拟合（按桶中位、等权最小二乘）：`ms/token = 17.91 + 0.0558 × context_k`（R² = 0.735）；32k 比 2k 贵 **1.67 ms/token**。

> **【AUDIT20 更正】** 原文写 `18.94 + 0.040`，按同表 7 个桶复算应为 `17.91 + 0.0558`（斜率被低估 28%、截距高 1.03 ms）。
> 复算方法：x̄=45.29k、ȳ=20.43 ms，Σ(x-x̄)(y-ȳ)/Σ(x-x̄)² = 0.0558。**结论（KV 只占 5%、关闭该方向）不受影响**，
> 因为那条只用到「1.24 ms ÷ 24.0 ms」。受影响的只是「余额随上下文增长」的斜率。

**形状不单调**（16–32k 反而比 8–16k 快），说明这一列是**混合口径**：桶里混了不同回复长度/接受率/热状态，
0–2k 那档 22.13 更是「短回复 + 首包开销」的产物。**所以只用它看量级，不当精确曲线。**

## 2 天花板算术（这是本轮的核心）

| 项 | 每 token 代价 @64k | 依据 |
|---|---:|---|
| KV 读（1.1 GB ÷ 884 GB/s） | **1.24 ms** | 17 KB/token（W871 停放图拟合）× 64k |
| 注意力 matmul（48 层 × 8 KV 头 × dim128，fp16 13 TFLOPS） | ~0.5 ms | 粗算，量级用 |
| **实测总计** | **24.0 ms** | 上表 |
| ⇒ 未被解释的部分 | **≈ 22 ms** | 专家读 / HC / GDN / 路由 / 选择器 |

⇒ **KV 侧最激进的改动也只能动那 1.24 ms**；把 K 或 V 再降一半，收益 ≤0.6 ms/token（2.5%）。
**结论：KV 量化不再是 decode 的候选方向**（质量上也没有动机，见 W871 的 K8V4 文献与外证）。

## 3 那 22 ms 是什么：候选与已排除项

W863 的窗口预算（单流 decode，同一台机）：**专家读 24.9% / HC 15.9% / attn 16% / GDN 14% / gemmd 9% / router 8%**。
按 24 ms/token 折算，专家读 ≈6 ms、HC ≈3.8、attn ≈3.8、GDN ≈3.4、router ≈1.9 —— 加起来仍不到 22。
**差额最可能落在「随上下文线性增长的那一项」**：QSA 的 block 选择器每步要给全上下文的块打分。

证据（引擎自己的日志，不是猜）：`qsa select` 在 128K、256 queries 下曾要 **2.71 ms**，
用 FP32 tiled scorer 降到 **0.587 ms**；生产已开 `STRATA_SELECT_SIMT=1`。
而我们这一支**新加过 `SIMT=2`**（tiles 32/128，**逐位与 =1 相同**，见 r-port 注释），
在 HIP 上以前被静默忽略、现在能真正生效 —— **这是一次「同位数、只换切分」的免费 A/B，还没测过。**
