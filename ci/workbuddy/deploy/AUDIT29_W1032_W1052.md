### 3.2 `CI_RUNS` + D7：证据行可以是 404（A29-2）

D7 的语义是「这个 exe 的构建 sha 有 CI run=success，或有显式豁免」。它只读第 4 列：
```python
if status == "success": return True, "%s -> run %s success" % (key, rid)
```
于是 `03509d1b → 4238161670`（少一位）也判 PASS。**这是 W1048 立 D7 时就埋下的**：
门核的是「表里写了 success」，不是「这个 run 真的 success」。新增的 `ci_runs_lint --live`
把 24 条 run 逐条查 API（conclusion、head_sha 前缀），自测里专门有一条「run 404 必须 FAIL」。

### 3.3 队列与账本各说一套（A29-1）

方案 §0.1 自称唯一排期源，账本说 R110/R112 判否、R106/R107 已结，队列却把 R110/R112 放在首位、
把 R106/R107 写成「新立待办」。这类「两份副本、没人比对」正是 AUDIT27 的 P0 主题；
`plan_lint` 只查「R 号有没有账」，不查「排期与状态是否一致」，所以一直 PASS。
