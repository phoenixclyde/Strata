> **修复自证判据的一次自纠**：首版判据是「反向 undo 必须逐字节等于原文」，但 U+002D 的反向映射**不唯一**，
> undo 会把所有连字符变成减号 => 断言必然失败。**是判据本身有缺陷，不是文件有问题。**
> 现判据三条：① 改后无禁用码位；② 行数不变且 `equal` 块逐行字节相同；
> ③ `replace` 块每对 (old,new) 满足 `new == 对 old 施加同一张替换表`，且 **old 行必含至少一个禁用码位**。

## 4 两处**实质错误**（本波审计的真正产出）

### 4.1 交接件把 `_w727` 的无效原因写错了 ---- 我误读了输出
- 原写法：*"那一轮 A/B 因驱动把 bench 路径硬编码成 `bench_ver.py` 而**跑错了探针**"*。
- **读原文后推翻**：`_w727.out.txt` 头部是 `bench=/data/bench_prefix.py`、正文是 `===== PREFIX ARM A-r1`，
  四臂全跑完、数据自洽 ---- **它是一轮完整有效运行**（探针没错）。
- **真正的问题**：它的 prompt 只有 **6,833 token（短于一个 chunk 8192）** => `--prompt-cache-tail` 的机制前提不成立，
  **是"测试域无效"，不是"工具跑错"**。
- 已改（并把这次更正记录写进交接件）。
- **教训**：我曾读过那个文件被中断时的**旧内容**，后来同文件名被完整结果**覆盖**，我拿旧印象写了结论。
  => **引用一个文件必须先重新读它当前的字节**，不能凭"我上次看过它"。

### 4.2 交付件把「两种测量实现」说成「两个互相独立的方法」
- 原文：0 节表头写"**两个互相独立的方法同向同量级**"，1.3 采纳规则写"**两方法独立同向**"，2.4 标题写"**本机独立复核**"。
- **实际**：上游 calibrate 与本机 A/B **同一台机、同一个引擎、同一时间窗**，只换了测量实现。
  这不是独立复现，**措辞过强**。
- 已改为"**交叉印证，非独立复现**"（4 处），并在采纳规则里写明原因。

### 4.3（附带）两条证据等级未标 ---- 已补
- 「chunk 对齐」机制：标为"**与观测一致的机制解释，尚未被独立证实**"。
- `0.7 GB` checkpoint RAM 成本：标为"**推算值，未实测 RAM 曲线**"。
- P34 的**适用区间**：补写"只在 ~10,000 token 一档实测；`> 16,384` 未测；`< 8,192` 无效"。
