## 3 结论

1. **59.9 可复现，且是稳态下界**：收敛值 **64.2 tok/s**。**归因更正（W752 审计 #4）**：原文写的"因为 hit 0.963 > 原来的 96.8%"**不等式为假**（0.963 < 0.968）。真实原因是**草稿每步净出更高**：原记录 `22/22` => net `32/(32-22)=3.20`、53.5 ms/step => 59.8；本次收敛 `23/23` => net `32/(32-23)=3.56`、55.4 ms/step => 64.2。**命中率更低而 tok/s 更高**，正是"两个协变量各自独立"的例证（W748 §3 的分解式仍然成立）。
2. **W741 §8 把 59.9 标为"不可复现"是错的，已更正**。它当时不可复现，只是因为**生产容器刚重启、专家缓存没热**。
3. **tok/s 的构成被钉死为两个协变量**：

       tok/s = 每步净出 / 每步耗时

   - **每步净出** = `gen / (gen - accepted)` ---- 由 **MTP 草稿命中** 决定，而草稿命中由**输出文本的可预测性**决定
     （本例的 `PARA x 150` 重复文本 + 那个问句 => 输出 158 字符、草稿必中）；
   - **每步耗时** = 52~55 ms（热）/ 75~92 ms（冷）---- 由 **专家 LRU 命中率** 决定（0.963 对 0.774）。

4. **这解释了 W743/W747 的"冷启动慢"**：同一台机器、同一 config，命中率 0.77 与 0.963 之间的单步耗时差 **1.5 倍**。

## 4 口径警告（引用 59 / 64 时必须带）

- 这是 **`gen=32` 的短生成 + 高度重复的英文 prompt**，**不代表常规性能**。常规（自然文本、gen 400~512）是 **43~49 tok/s**。
- 同一条 payload，**"追加一句"与"不追加"的输出不同**（158 对 181 字符）=> 草稿命中率不同（22/22 对 15~16/18）=> tok/s 差一截（60+ 对 33~51）。
- 任何"我们快到 64"的引用，必须同时给 **gen / drafts 接受 / hit rate** 三个数，否则就是混比（与 W744 的纪律一致）。
