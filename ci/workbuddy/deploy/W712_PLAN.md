## 1 为什么是这个顺序（判据，不是感觉）

### A2 先做，是因为"引擎变了，账就得重开"
现有解码读数（42.9 tok/s / MTP 接受 61-66%）都是 **0.1.40.1/0.1.40.2 时代**的。
本波已完成**升级 + 切换 + 复验 + 中性 A/B**（`W712_UPGRADE.md` §3）：
冷预填 456.1 vs 457.6 tok/s（**-0.33%**）、温 TTFT 5.753 vs 5.853 s、`reused` 均 16384
=> **冷预填 / 温 TTFT / 前缀复用 / 缓存命中四类口径上，两版落在分辨力内，不可分辨**。

但本次 A/B 的生成只有 32 token，**不是解码基准**。
=> 还缺一条 **0.1.40.4 的干净解码分母**（512 token x 3，`temperature 0 / top_k 1`，预热 2 条，ctx 262144）。

**A2 的验收判据**（Z0=off，同一 prompt、同一参数）：
1. 服务面：`verify_config.py` FAIL=0、`/proc` cmdline 三项在、LIVE md5 = `d2b10f0c...bea`（本波已全过）；
2. 性能面：512 token x 3 取中位；与 0.1.40.2 时代同类读数比，**落在解码分辨力（9.5-15%）内即记"未见差异"**；
3. 结果写回 `W712_UPGRADE.md` §3，作为 B 档所有 A/B 的**新分母**。

### B1 排第二，是因为它可能推翻一个已采纳项
`--prompt-cache-every 8192` 的机制前提是"可复用前缀必须与 prefill chunk（8192）对齐"（W709 §2）。
但本机日常用法是**短会话 + 工具调用**（WorkBuddy 交互），prompt 常在 1k~6k。
**chunk 对齐意味着：< 8192 的 prompt 一个 checkpoint 都放不下 => 该档可能完全无复用。**
若如此，8192 对短会话至少是"无害但无用"；要确认它**不是有害**（比如引入额外 RAM 压力或打断别的缓存路径）。

**B1 配方**：
- 探针 `deploy/data/bench_prefix.py`（长度可调）造两条：**P-short 约 4,600 tok**、**P-long 约 24,000 tok**（刻意不取 8192 的整数倍）；
- 臂：`every 8192`（现役）vs `every 16384`（旧默认）vs `every 32768`（>16k 档候选，16384 的倍数）；
- 读 `reused`（机制判据）与**温 TTFT**（体验判据），每臂 2 轮交叉；
- 结论写两行：`<8k 档：8192 相对 16384 = ?`；`>16k 档：32768 相对 8192 = ?`。
- **RAM 代价要一起记**：官方 help 记约 118 MB/checkpoint；W709 的"上限约 0.7 GB"是**推算未实测**，本档顺手实测一次。

### B2 排第三，是因为它打的是**真实痛感**
WorkBuddy 每轮工具调用都是一次短 prompt 往返。官方口径：`STRATA_PREFILL_CPU_SHARE=auto` 对 < 1024 token 的 chunk
快 19-35%，2K 以上不变。
**陷阱（必须写进结论）**：官方明说**答案非逐位相同**（CPU/GPU 舍入不同，mean KL 0.006，22 条里 19 条同 top token）=> 它是"速度换确定性"的开关，验收要同时报 TTFT 与**非一致性**，不能只报快了多少。

**B2 配方**：短探针约 600 tok + `max_tokens 16`，测 TTFT；A/B 各 2 轮（ABBA 交叉）；改法 = config 的 `env` 加键，**只需 restart，不必重建容器**（`child_env(cfg)` 会传下去）。

### B6 本波新增：`STRATA_MMVQ_IL` 到底命中没有
register 里 `P30 STRATA_MMVQ_IL` 状态 CANDIDATE，备注"本机是否命中未验"。
它是 0.1.40.2 引入、**默认开**的（"2-4 token verify windows read each weight block once"），官方标注
适用面是 "RTX 30 series and newer"。
**先读源码判定 gfx906 是否走那条分支**：不命中就直接落 `REJECTED`（本机不适用），**不必发车**；
命中则它已经是默认开，也无需改参数 - 两种结果都是"一条 register 结论"，成本 15 分钟。

### B4 需要采样口径，这是硬前提
W709 §3 已写明：`STRATA_SPEC_GUMBEL=1` 在**贪心口径下是空操作**，必须 `temperature > 0`。
本机现役服务建议口径是 `temperature 0.6 / top_p 0.95 / top_k 20`（见 `configs/workbuddy-strata166.md` §4）
=> 测试必须用**这个口径**（或 0.7），并报**接受长度分布**，而不是只报 tok/s。

### B5 只能走机制判据
预期 ~3%，**低于解码分辨力 9.5-15%** => 吞吐口径永远得不出结论。
改用引擎自带窗口计数当**机制判据**（生效 / 不生效），吞吐只作旁证。
