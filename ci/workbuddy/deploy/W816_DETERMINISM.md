> 不是"每次都不同"；②指纹**跨启动可枚举**（`87ce959e` 在三次启动的 warm 组都出现、`433f4e0e` 三次主组都出现）。

## 0 一句话

> **在本机上，`temperature 0` ≠ 可复现。** 同一进程、同一输入、连发 6 次，出 **3-5 个不同答案**；
> 所以**任何"跨请求 / 跨重启比答案"的判据都无效**——质量门只能用 teacher-forced（同一次前向）或统计口径。
> （仅限**生成路径**；teacher-forced 在 `share=0` 下可复现，见顶部横幅。）

### 0.1 AUDIT11 从原始件 `w816_det_*.txt` 补的两条（原文未写）

**① 不是"每次都不同"**：`=== ARM B1` 里先跑了一组 `reps=2` 的短请求，标签 `DET tag=B1-warm reps=2 **unique=1 SAME**`
—— 两次**完全相同**（`87ce959e` / n=168）。同一次启动的主组 `reps=3` 才是 3 个不同。B2-warm / B3-warm 则是 2 个不同。
⇒ 正确表述是「**多数情况不复现，但存在复现的样本**」，不是"必然不同"。

**② 吸引子是有限且跨启动稳定的**（这是原文最有价值但漏掉的结构）：

| 指纹 | n | 出现在 |
|---|---:|---|
| `87ce959e` | 168 | **B1-warm、B2-warm、B3-warm 三次启动都出现** |
| `7ad09630` | 173 | B2-warm、B3-warm 的 R0 |
| `433f4e0e` | 351 | **B1 / B2 / B3 三次主组都出现** |
| `0208d7b6` | 354 | B2 的 R0+R1、B3 的 R0 |
| `9eba0382` / `2f254f14` / `386d8492` | 343 / 357 / 346 | 各一次 |

⇒ 不是无界发散，是**在一个有限吸引子集合里跳**。对判据的含义：逐字比仍然不行，
但"落在哪个吸引子"是稳定的 —— 若要统计口径，可以按"吸引子命中率"记，而不是按"字符相似度"记。

**③ 首请求带约 1 s 冷启动**：同文件的 `TR` 行 —— `read 69 tokens (batched) in **1018.3 ms**`（首请求）、
`167.7 ms`（第二次）、之后稳定 **57-65 ms**。这条后来解释了 W822 的 427 与今天的 525（差 1.15 s）。

## 1 先排除「启动期」这个假设

W814 的解释本来是"两次启动选了不同的提示路径"（上游 0.2.5 发布说明：「The old timing guess changed answers
between runs」）。W816 直接测**同一个实例内**：

| 启动 | 连发 3 次（64 token，`temperature 0`） | 不同答案数 | 该臂的 chunk |
|---|---|---:|---|
| B1 | `9eba0382` / `2f254f14` / `433f4e0e` | **3 / 3** | `lent 191 slots for 256 tokens` |
| B2 | `0208d7b6` / `0208d7b6` / `433f4e0e` | 2 / 3 | 同上 |
| B3 | `0208d7b6` / `433f4e0e` / `386d8492` | **3 / 3** | 同上 |

**chunk 三臂逐字相同（191 slots / 256 tokens）**，答案却在同一个进程里就变 ⇒ **不是启动期选路径**。
假设 1 否。

### 1.1 顺手排除「专家档案跨启动变化」

`--expert-profile /src/data/expert-profile.bin`（**读**，在镜像里）与
`--expert-profile-save /data/profiles/huihui-ud-iq4_xs-learned.bin`（**写**）是两个文件；
日志每次都是 `profile /src/data/expert-profile.bin: 24576 ranked pairs, built for 24576 slots`，
`learned.bin` 只写不读（`ls` 的 mtime 会更新，但没有任何一行读它）。假设 2 否。

## 2 定量：多吸引子，不是"热身之后会稳定"

同一 prompt、96 token、连发 N 次，算两两公共前缀（`mt_det2.py`）。

**P0（4 次）**：3 个不同答案

| 对 | 公共前缀 |
|---|---|
| R0-R1 / R0-R2 / R0-R3 | **49 字符（≈13 token）** |
| R1-R2 / R1-R3 | 295 字符 |
| R2-R3 | **528（逐字相同）** |

**P1（6 次）**：3 个不同答案，且**非单调**

| 分组 | 样本 | 长度 |
|---|---|---|
| A | R0 = R3 = R4 | 554（三者逐字相同） |
| B | R1 = R2 | 528 |
| C | R5 | 558（与 A 公共前缀 189） |

⇒ 不是"前两次不稳、之后收敛"，而是**在几个吸引子之间跳**：早期（~13 token）遇到一个近似平局，
不同的归约顺序把它翻过去，之后各自自洽地写下去。**这是浮点层面的事，不是采样**（`temperature 0` 走 argmax）。

## 3 逐一试过、都否掉的三条路

| 假设 | 做法 | 结果 |
|---|---|---|
| 关掉投机解码 | `--spec 0` | **做不到**：引擎拒绝启动，日志逐字 `is a native (IQ) pack: it needs --native SHARD1, --spec T (T >= 2) and --prefill CHUNK` ⇒ **本 pack 上不存在"无投机"这一档** |
| 关掉路由尾跳 | `STRATA_ROUTE_TAIL_SKIP=0`（W818） | **更差**：6 次出 **5 个**不同答案（生产是 3 个）⇒ 尾跳不是元凶 |
| 启动期选路径 / 专家档案 | 见 §1 | 否 |

> 上游旁证：#4106（2026-10-25，Strix Halo，**v0.2.4**）也报告"greedy output diverges more"，
> 24 个短提示里 Strata 与 llama.cpp 只有 5/24 逐字吻合，且 `STRATA_HC_Q8=0` 前后 14/24 吻合
> —— 说明**同版本上"改任一数值路径就改答案"是普遍现象**，与本机一致。

## 4 对项目的后果（需要立刻记账的部分）

1. **`--ple-io` / `--ple-io ram` 的答案等价性，在本构建上判不了**（W814 已登记为"未决"，现在有了解释：
   判据本身的噪声比要判的效应还大）。要判只能等升级到能钉住路径的版本，或走统计口径。
2. **凡是"跨请求比答案"的历史判据都要降级**。逐条过了一遍 register：
   - `P136`（B6 MMVQ）、`P107/P108`（rocBLAS 表）、`W809` 的九开关 —— 这些"bitwise 全部通过"
     都是**同一个进程内、同一输入、两种内核**的 memcmp，**不受影响**；
   - `P141` 的答案等价性 —— **作废**（判不了）；
   - 解码侧 KL 门（`kl_gate`/`kl_pair`）是 **teacher-forced**（一次前向里给每个位置打分），
     **方法仍成立**，但要知道它的跨重启噪声地板不是 0（本项目实测底噪 0，那是同一次前向内）。
3. **给用户的实话**：同一句话问两遍，稳态下仍可能得到不同措辞（尤其长回答、开放写作）。
   要"可复现"，目前唯一稳的办法是**不要拿输出文本当判据**（用评分/单测/结构化字段），
   或等上游把路径钉死的那一版。
