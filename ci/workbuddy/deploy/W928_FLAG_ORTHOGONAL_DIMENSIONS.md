# W928 · 「W4A4/W4A8 二选一」是错的：四个正交维度，以及 k8v8 的真身

> 触发：机主 2026-11-04 00:3x ——「你不能两个都有，要用哪个用哪个，你这个是二选一的？那 k8v8 呢？」
> 本轮零改动生产，全部源码 + 参数册 + 源码注释取证。

---

## 0 结论

**我上一轮把两件不同维度的事说成了一件，这是错的。** 正确的框架是**四个正交维度**，任意组合都成立：

| 维度 | 取值 | 谁决定 | 是否可混合 |
|---|---|---|---|
| ① **权重格式** | Q4_K(u4) / Q5_1 / Q8_0 / Q4_0 / NVFP4 | pack / GGUF，已定死 | 按张量，天然混合（W910：gate/up=Q4_K、down=Q5_1） |
| ② **激活精度** | Q8_1(int8) / int4 / FP4(E2M1) | MMQ 的量化器 | **可按类型分别设**（MMQ 每类型一个编译实例） |
| ③ **指令** | `v_dot4`(4MAC) / `v_dot8`(8MAC, i4×i4) / fp16 FMA | 由 ①② 决定，不是自由选择 | 同一内核里可并存 |
| ④ **KV 格式** | fp16 / **int8(=k8v8)** / q4_0 / k8v4 | `--kv` | 与 ①②③ **完全正交** |

**「W4A4 / W4A8」是维度②的两个档位，不是全局二选一**；「dot8 / dp4a」是维度③，由②决定。**我们的代码里 W4A4 与 W4A8 本来就是两个并存的 TU。**

**k8v8 不是待实现的新东西**：它就是 `--kv int8`（KV_MODE 1），`generate.cpp:3835` 的白名单里写得明明白白。它对应队列里的 **M3**，从 W835 挂到现在一直 OPEN。

## 1 源码证据：W4A4 与 W4A8 并存

```
src/prefill/mmq_nvfp4_w4a8.cu   1360 B   → 编进 strata_mmq      （默认路径）
src/prefill/mmq_nvfp4_w4a4.cu   2612 B   → 单独编成 strata_mmq_w4a4（需 sm_120a）
```

`CMakeLists.txt:2201` 原文：

> `# NVFP4: W4A8 (default) in mmq_nvfp4_w4a8.cu with the plain architectures; the opt-in W4A4 needs RTX 50's FP4 MMA,`

w4a8 那份的头注释把两者的差别说穿了：

> *"On sm_120 mmq.cuh compiles NVFP4 as FP4 x FP4 (W4A4): the activations are rounded to E2M1 too, and the first token's distribution **drifts by KL 0.0004-0.03** from the exact FP16 prefill (8 prompts)."*

两条关键事实：
1. **同一份 `mmq.cuh`，靠 `#define blackwell_mma_available(cc) false` 一句话就切成两个档位** —— 换算术路径的成本极低，证明"档位"是个开关，不是架构决定。
2. **上游自己做 W4A4，精度就是 KL 0.0004–0.03**（跨两个数量级）。我们的门是 **0.005**，正好落在它区间的中段 ⇒ **W4A4 过不过门是五五开，必须实测，不能预判。**

（注意：这两个 TU 是 NVFP4/Blackwell 的，在 gfx906 上**根本不会执行** —— `dot8` 命中 0，它们走 FP4 MMA。引用它们只为证明"档位可并存"这个设计模式。）

## 2 dot8 该在哪里用：按权重位宽分派，不是按全局偏好

`v_dot8_i32_i4` 是 **i4×i4**（W909 实跑：nibble{1..8} 得 20 = 1+…+7−8）。所以能不能用，**只看两边的位宽**：

| 权重 | 位宽 | 能否 dot8 | 本模型用量 |
|---|---|---|---|
| **Q4_K** (u4) | 4 | ✅（`^0x88888888` + `8·Σb` 修正，W927 实跑 ALL MATCH） | **gate/up 47/48 层** |
| Q4_0 / IQ4_NL | 4 | ✅ | PLE 表（不进 MMQ） |
| **Q5_1 / Q5_K** | **5** | ❌ 塞不进 4-bit 位宽 | **down 43 层** |
| Q8_0 | 8 | ❌ | down 5 层 + 主 GGUF 8.6% |

**⇒ 同一层里可以「gate/up 走 dot8、down 走 dp4a」—— 这就是你说的「两个都有」。**

而 MMQ 本来就是**按类型编译实例**的（`DECL_MMQ_CASE(GGML_TYPE_xxx)`，`mmq_tab` 给 9 个类型各编一个），所以「按类型选激活精度」在工程上是**加一个实例**，不是改全局开关。

## 3 Amdahl 修正：从 5.5% 降到 3.2%（上一轮算错了覆盖面）

W927 用「MMQ 占 prefill 34.6%」算上限，但那是 **gate/up 20.8% + down 13.8% 的和**；dot8 只覆盖 gate/up（Q4_K），**down 的 Q5_1/Q8_0 一位都覆盖不到**。

用 W926 的 prefill 分解重算：

```
dot8 覆盖面 = gemm gate/up 20.8% × (Q4_K 占 47/48 = 97.9%)
            = 20.4% of prefill
该块内 dp4a 指令占比（R58）= 5184 / 9713 = 53.4%
W4A4 后 dp4a 减半 ⇒ 该块指令 −26.7%
× VALU 占用 0.81
= 20.4% × 26.7% × 0.81 = 4.41% of prefill
× prefill 占端到端 73.1%
= 3.22% 端到端
```

**噪声门 = 2×CV = 3.2%。⇒ dot8 的理论上限正好压在门上。**

按 W925 判据：`> 2×CV 且可消除 → 才进代码`。这里是"等于"，属边缘区，且：
- R51 的先例是**理论 4.15% → 实测 −6~−10%**；
- W927 的 5.5% 是错的（多算了一半覆盖面）。

## 4 k8v8 的真身与它的真实账

`--kv` 白名单（`generate.cpp:3835`）：`fp16` / `int8` / `q4_0` / `k8v4` —— **没有叫 `k8v8` 的**，因为 **`int8` 就是它**（K 和 V 都 int8，KV_MODE 1）。

源码注释（`qsa_prompt_attn.cu:89`）：

```cpp
// KV_MODE 1: int8 codes + fp16 scale per 64 values. KV_MODE 0: fp16 values (scales 1).
// KV_MODE 3 (hybrid K8V4): K as mode 1, V as mode 0 - the row's q4_0 blocks are
//   dequantized to fp16 at gather, so everything downstream of the load is the mode-0 V path
```

### 4.1 已有实测账（P04 / P50 / P247）

| 项 | k8v4（现役） | **int8（=k8v8）** |
|---|---|---|
| 显存 / cell | **816 B** | 1056 B（**+29.4%**） |
| 省下的显存 | 基准 | −3.8 GiB ≈ **−1700 专家槽** |
| decode 影响 | 基准 | **−7.7% ~ −16.6%**（槽少） |
| **质量 KL（中位）** | 0.0704 | **0.0416（更好）** |
| needle 任务门 | 6/6 FOUND | 未做 |

**P04 的 AUDIT21/C5 澄清必须一起读**：k8v4 被采纳的理由是「**省 3.8 GiB VRAM**」，**不是「质量已证」** —— W767 明写方向未判、W769 结论是「分布门被专家驻留布局主导，原理上无法单独裁决 `--kv`」。

⇒ **int8 的质量数字比 k8v4 好（0.0416 < 0.0704），代价是 3.8 GiB 显存换 decode −7.7~16.6%。** 这是**真 trade-off**，不是"二选一"。

### 4.2 未核的那一半：prefill 代价（M3，W835 立、一直 OPEN）

k8v4 的 V 是 q4_0，**gather 时反量化成 fp16**（多一次 4-bit 解包 + scale 乘）。int8 的 V 是 int8，少这一次。但 int8 多读 29.4% 字节。**净效应不明，从来没测过。**

M3 的原文：*"KI 实测 attention prefill 慢 2.5–2.7×；我们 --kv k8v4 未核"*。

**这条比 dot8 便宜得多**：零代码、只换一个 CLI 参数 + 一次重启。

## 5 三维组合矩阵：哪些能同时要

| 组合 | 成立? | 资源代价 | 备注 |
|---|---|---|---|
| W4A4(dot8) 用于 gate/up **＋** dp4a 用于 down | ✅ | 0 显存 | 按类型分实例，正交 |
| 上面这套 **＋** `--kv int8`(k8v8) | ✅ | +3.8 GiB（−1700 槽） | KV 与 MMQ 完全正交 |
| 上面这套 **＋** PLE mlock（现役 P256） | ✅ | −26.8 GiB 宿主可用 | 已采纳，预防性 |
| W4A4 用于 **down** | ❌ | — | Q5_1 是 5-bit，塞不进 i4 |
| dot8 用于 **KV 的 P·V** | ⚠️ | 需 P 也量化成 int4 | K100LC-RT4 做过（gfx926，KL 4.2e-6），但那是重写 attention 内核 |
| W4A4 **全局**（包括 Q8_0） | ❌ | — | Q8_0 是 8-bit |

⇒ **「两个都有」在四个维度上都成立**；不成立的只有"位宽不匹配"那两格。

## 6 判据与队列调整

### R74（W4A4 精度门）—— 保留，但预期要说清

- **先做**：不改内核，先用现有工具离线算 int4 激活量化 vs Q8_1 的 KL（XOR + 修正项已验证位精确，量化器可以离线模拟）。
- **门**：KL ≤ 0.005、top-1 ≥ 99%（分辨率 0.0032）。
- **先验**：上游自己的 W4A4 是 **KL 0.0004–0.03**，跨两个数量级 ⇒ **五五开**。
- **过了才谈工程**：即使过门，端到端上限 **3.22% = 噪声门**，实测大概率测不出（R51 前例）。

### M3（k8v8 的 prefill 代价）—— 提级到 R74 之前

- **零代码**：`--kv k8v4` → `--kv int8`，一次重启。
- **量什么**：同 prompt 的 `strata prefill timing: qsa attn` 绝对毫秒（k8v4 vs int8）。
- **为什么先做**：①它是唯一"可能免费"的一条（质量更好 + prefill 可能更快，代价只是显存）；②它直接决定 R74 该不该继续 —— 如果 attention 在 int8 下 prefill 明显更快，那说明 V 的 q4 解包是真实成本，dot8 方向（少解包）的先验变强；如果没差别，说明 attention 早就是带宽/其他受限，dot8 的 3.22% 更没戏。

## 7 我这一轮的两个错（记账）

1. **把「档位」和「指令」说成一件事**：写成「W4A8 退回混合、W4A4 全量」，暗示二选一。实际是四维正交，代码里 W4A4/W4A8 两个 TU 并存就是证明。
2. **Amdahl 覆盖面算多了**：用 MMQ 整体 34.6%，而 dot8 只覆盖 gate/up 的 20.4% ⇒ 上限从 5.5% 修正到 **3.22%**。

**教训（写进方法）**：报"某优化能覆盖多少"时，必须逐项核对**它的作用对象**（张量类型 / 位宽 / 相位），不能用"子系统总量"代替"它实际能碰到的量"。这与 W925 的"分母纪律"是同一族错误的第二次出现。
