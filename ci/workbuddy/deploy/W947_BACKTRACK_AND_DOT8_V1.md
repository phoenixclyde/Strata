### 2.1 指令可用（A 级）

- `__builtin_amdgcn_sdot8(a, b, c, false)` 在 `--offload-arch=gfx906` 下编译、运行 `no error`；
- W909 已实测语义：nibble `0xFF` = **−1**（signed i4），`{1..8}·{1..1} = 36`；
- 与 `sdot4` 同一份代码路径，只是把 4 个数换成 8 个数。

### 2.2 数学已证（A 级，20000 组随机）

Q4_K 的 u4 ∈ [0,15] 经 `x ^ 0x88888888` 后按 **signed i4** 解释，恰为 `q − 8`：

```
sum((q-8)*a) + 8*sum(a)  ==  sum(q*a)      # a ∈ [-8,7], q ∈ [0,15]
violations 0 / 20000
```

⇒ 用 `sdot8(q ^ 0x8…, a)` 得到 Σ(q−8)a，加 `8·Σa` 即得 Q4_K 需要的 Σq·a；
min 项直接乘 `Σa`（该子块内 `dmin*m` 是常数，按 8 值拆分求和等价）。
**注意**：我第一版验证脚本写成 `((q^8)-8)` 得到 19433/20000 违反 —— 那是脚本错，不是数学错（`^8` 之后必须按 s4 解释，不能线减 8）。

### 2.3 内核数值未对齐（**未通过**，已在定位）

```
M=64  dp4a rel_l2 = 0.99481   dot8 rel_l2 = 0.99590   (vs fp32, same weights)
```

**两条臂都错到 0.99**，说明不是 dot 指令的问题，而是**共用路径**（权重打包 `pack8_u4` / `get_scale_min_k4` / `_Float16` 的 d、dmin 读取 / 参考实现）之一。

最可能的根因：`BlockQ4K` 里 `_Float16 d, dmin` 在 **x86 host 侧**的 `(float)` 转换。下一版改成
`uint16_t` 存位模式 + 显式 `__half2float(__ushort_as_half(x))`，host/device 同一函数。

### 2.4 吞吐：本版**不可用**

```
dp4a 0.383 ms 0.55 TMAC/s ; dot8 0.698 ms 0.30 TMAC/s ; speedup 0.55x
```

两边都只有 0.3–0.55 TMAC/s，而生产 MMQ 是 **7.7 TMAC/s** ⇒ 这个原型的瓶颈是**朴素的每 8 值标量循环**
（`pack8_u4` 的 8 次位操作 + 子块解析），不是 dot 指令。**不能拿它判 dot8 的收益**，也不能反过来判负。
