### A5 `W864` §3 的直线拟合混了两条代价不同的路径

- 位置：`W864_RESUME_COST.md:78`「截距 ≈ 390 ms，斜率 ≈ 2.3 ms/token」。
- 复算：表里 `443 tok / 87 新读 / 828 ms` 这一点，按 390 + 2.3×87 = 590 ms，实测 **828**，偏 +238 ms。
- 原因（W867 已测出）：尾巴 ≤ `--short-read`(64) 走 **verify 窗口 13–16 ms/token**，> 64 走 **批 3.4–4.0 ms/token**。87 个新 token 里 64 个走窗口 ⇒ 该点是**两段拼接**，不能落在单一直线上。
- 影响：「2.3 ms/token」既不是窗口斜率也不是批斜率，是混合值；后续 W866/W867 已分别给出两条线的斜率，但 W864 未标。
- 建议：§3 加「该直线只对 batch 路径成立；窗口路径见 W867」的限定。

### A6 `W866` §3 的 `--short-read` 收益预测被 `W867` 实测证伪，未标注

### A9 `W869` §4 的「87%」与它自己的数算不符

- 位置：`W869_PARK_IS_THE_COST.md` §4「23.7 ms ≈ 260 MB / 13.2 GB/s 的 **87%**」。
- 复算：260 MB ÷ 13.2 GB/s = **19.7 ms**；19.7 ÷ 23.7 = **83.1%**。

### A10 `W871` 的 cell 与 token 两个口径混用，差 20 倍

- 位置：`W871_KV_BASELINE_AND_DECODE.md` §1 表「每 cell 字节 **816 B**」与 §0-2「弹性 KV 初值 **16384 cell ≈ 0.27 GB**」。
- 复算：**816 B × 16384 = 13.4 MB**，而文中写 **0.27 GB（276 MB）**，差 **20.6 倍**。
- 能对上 0.27 GB 的只有另一个口径：**16.7 KB/token × 16384 token = 274 MB** ✓。
- 结论：`16384` 是**token 位置数**，不是「cell 数」；816 B/cell 是 KV 格式比较用的**相对**单位，与 KB/token 不能直接相乘。
- 影响：同一张表里两个口径并列，任何按 `816 × 16384` 复算的人都会得到 13.4 MB。W872 又引用了「17 KB/token」，但没有复现这个矛盾。
- 建议：§1 表下加注「cell ≠ token：16.7 KB/token 是实际占用口径，816 B/cell 只用于 k8v4 vs int8 的相对比较」。

### A11 `W872` 的拟合式与同表数据复算不符

- 文中斜率 **0.040** 比复算低 **28%**，截距高 1.04 ms。
- 影响：结论「KV 只占 5%、关闭该方向」**不受影响**（它只用 1.24 ms / 24.0 ms），但「32k 比 2k 贵 1.2 ms」变成 **1.67 ms**，而「未被解释的余额」也相应变化。
- 建议：要么改数，要么给出拟合所用的点与权重（文中说「按桶中位、等权」，但给出的参数复现不出来）。
