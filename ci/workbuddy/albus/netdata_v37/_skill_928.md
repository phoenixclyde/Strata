
### 9.28 v40 整套版式重写（2026-11-05 01:4x）
机主连续两轮否掉 v38/v39（「真难看」「更丑了，起码的整齐都没有」）。诊断结论：
**不是审美问题，是 CSS 成了三层补丁**。v37→v39 每个选择器在文件不同段落各定义一次
（`.hostgrid` 3 次、`.tiles` 5 次、`.drow` 3 次、`.kpi` 4 次），同特异性靠出现顺序取胜，
改一处被后面覆盖 —— 表现就是「对齐时好时坏」。**正确做法是把 `<style>` 整段重写，
每个选择器只出现一次**，而不是继续在末尾追加覆盖。改完单次验证通过。

可复用的三条布局陷阱（都实测复现过）：
1. **`body{min-height:100vh}` 不能当弹性容器的高度基准**。容器高度不确定 → flex 子项
   （main）的 `flex-shrink` 永不触发 → 内容一旦高于视口就整体溢出（实测 +48px）。
   要 `height:100vh`（配 `overflow-y:auto` 兜矮屏）。
2. **`.card{min-height:min-content}` 会让卡片比 grid 分给它的行更高**（行 302 / 卡 340 →
   越出栅格压到页脚）。卡片一律 `min-height:0`，下限分别给记分板（72）和整页 main（780）。
3. **SVG 图表的 viewBox 会自激**：viewBox 决定固有比例 → 影响 max-content → 影响行高 →
   又决定图高 → 再写回 viewBox（每 2s 一次，越滚越大）。断法：
   `flex:1 1 0;height:0;min-height:72px`（基准高由 flex 决定，测量值即最终值）。
   另外 `height:auto` 会让 600x96 的 viewBox 撑到 155px 并把文字拉成长条。
   判据：**任何「高度由内容决定、内容又由高度决定」的环，必须在 CSS 层断掉**。

顶栏 23 格：原 `flex-wrap` 的换行点由**数值字符长度**决定（显存 883.40x / 3084.69x 差两个字符
就把「闸门」整组顶到下一行），同一台机器会出现两种排法。改 `display:grid` 两列等分 → 四组恒定。

其它定案：
- 主机卡从三栏改两栏（左=38px 主值+内存条+8 瓦片，右=存储表+走势）。三栏时中栏只有 8 瓦片，
  底下凭空空 150px —— 「空多空少」的根源不是留白不够，是**栏与栏内容量不匹配**。
  两栏后瓦片用 `grid-auto-rows:minmax(0,1fr)` 自撑满，左栏底边与右栏齐平。
- 存储表 = 一个表头 + 两行数据（原来每行重复 读/写/温度/寿命 四个标签，两行盘就是八个小标签）。
- 尺度统一：字号 7 档（10/11/12/15/22/28/38）、间距 4 的倍数、`.bar .lab` 标签与数值贴在一起
  （`justify-content:space-between` 在 700px 宽的条上会把两者拉到两端，读起来像两件事）。
- 记分板左右各内缩 21px（= 页边 20 + 边框 1 + 卡内边 20），文字与卡片内容对齐而不是与卡片边框对齐。
