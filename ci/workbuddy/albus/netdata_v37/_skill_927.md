
### 9.27 v38 版面重做：从「堆数据」到「有层级」（2026-11-05）

机主三连：「真难看 / 信息重复 / 空多空少 / 字体不统一 / 你整体看啊」。**这不是修 CSS，是重排信息架构。**

**量化前后的硬指标**（Chrome 注入探针量，1920x1078 → vh 980）：

| | v37d | v38 |
|---|---|---|
| 页面高度 | 1066~1446（视宽度） | **980（正好一屏，无滚动）** |
| 实际渲染字号档位 | 13 种 | **6 种**（11 / 12 / 15 / 19 / 28 / 34） |
| CSS 里 font-size 声明 | 18 种 / 58 处 | 5 档 token + 个别固定值 |
| 死规则 | 27 条（.ovgpu* / .ssd* / .dcell*） | 0 |
| 总览重复项 | 3 行 GPU 明细 + 8 KPI | 只剩 8 个**聚合** KPI |

四条改法（每条都对应他点的一句）：
1. **信息重复** → 删掉总览右侧 MI50/2070/CPU 三行。它们把两张显卡卡片里的 温度/功耗/显存/风扇 又抄了一遍。
   CPU 功耗与风扇挪进主机卡瓦片，数据不丢；利用率/显存/功耗只在「聚合 KPI + 各自卡片」两处出现（summary/detail 关系，不是复述）。
   同时下掉主机卡里「系统盘已用/可用」「磁盘读/写」四个瓦片 —— 文件系统占用进了存储行元信息，读写在存储行逐盘给出。
2. **空多空少** → 根因是卡片行用 1.1fr/0.9fr 硬撑 + `svg{flex:1}` 吸收全部余量：两张显卡卡的图表区各空出 ~200px。
   改为 `minmax(min-content, Nfr)`：矮屏按内容高度走（不溢出），高屏按比例分配（图表跟着长高，而不是卡片底部留黑）。
   `svg` 必须给 `height` 基准值 —— `height:auto` 会按 viewBox 600:96 的比例撑到 155px（实测踩到）。
3. **字体不统一** → 收到 6 档：11(微标) / 12(说明) / 15(正文) / 19(瓦片值) / 28(KPI·环形) / 34(主环)。
   数字全部 tabular-nums；单位一律小一号 + dim。状态条从 11.5 抬到 12（不再比正文还小）。
4. **整体看** → 主机卡重排为三栏：①环比条 ②传感器/网络瓦片 ③存储条 + 走势。存储行改成
   「盘名 + 元信息（容量/已用/累计写入/通电）+ 读 / 写 / 温度 / 寿命 / 状态」，一行里只有两个数字在跳。

**踩坑记录**（都花了时间）：
- `height:auto` + viewBox 让 svg 长到 155px；`flex:1` 在 grid fr 行里会把卡片撑高。
- `.hostgrid > div > .tiles`（0,2,1）压过 `.hostgrid .tiles`（0,2,0）→ 主机瓦片一直排成 4 列。改成 `.hostgrid .hcol .tiles`。
- 切片替换函数体时**连同该区间里的工具函数一起删掉**（setKpi/pairUnits）→ 总览 8 格全 `--`。
  改法：切片前先 grep 该区间定义了哪些 function。
- 每次插入 CSS/HTML 都是 LF，文件变混行尾 → 之后按 CRLF 写 old 串必然 0 命中。**改前先归一化**。
