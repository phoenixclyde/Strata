
### 9.31 磁盘卡走势图的三个坑（2026-11-05 03:00）
机主三连问：「你表征什么？没有图例。到底几条线？左边两条右边一条吗？」—— 三个都中，而且是真 bug 不是审美。

1. **[bug] `disk.io` 的 writes 是负值**。netdata 这张图是**镜像双向图**：`reads` 在 0 上方为正，`writes` 在 0 下方为负。
   取证一条命令就够：
   `curl -s 'http://<host>:19999/api/v1/data?chart=disk.sda&after=-60&points=30&format=json'`
   → `"writes"` 列是 `-1033.4 / -602.9 / -6.9`。
   旧实现直接 `y = H - v/scale*H`，负值 => `y > H` => 落在 viewBox 外被裁 => **写线整条不可见**，
   于是"左边两条右边一条"（其实是同一路数据在不同时刻的峰值差异造成的错觉）。
   修法：一律 `Math.abs()`，并按方向各自归一。
   **判据：画任何 netdata 序列前先看该维度是否有负值**（dpkg 里 `disk.io` / `net` 的 out 都是负的）。

2. **[bug] 闭合填充路径的收边段会被描边**。把面积图和折线用同一条 `path` 时，
   `... L W mid L 0 mid Z` 这一段回到零线，也被 `stroke` 画出来 => 零线变成 1.4px 彩色粗线，
   看上去像多出一条线。修法：`fill` 用闭合 path（`stroke="none"`），`stroke` 另用开放 path。

3. **[设计] 两路共用一条零线 = 看不出几条线**。某一路恒 0 时它的折线正好压在零线上。
   改为**上下两条独立泳道**：各自基线、中间留 10px 空隙、基线用本序列色 32% 画细线。
   恒零的那一路也留得下一条彩色细线，读得出"这条是 0"。

配套：
- 图例就放在**读/写两行的标签前**（7×4 色块，与线同色），不额外占一行；走势块头行左边「近 60 s」、右边「▬上读 ▬下写」。
- 纵轴用「上一轮刻度 ×0.88 衰减」当下限，否则每 2s 峰值一变整图跳一下，趋势没法看。
- 空间紧时先压 SMART 三格（标签上/数值下 → 单行），别去动 20px 的读数档位。
