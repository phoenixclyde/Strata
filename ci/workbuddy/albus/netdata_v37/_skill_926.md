
### 9.26 v37d 把「存储」收进「主机」右栏，恢复一屏（2026-11-05）

机主：「页面下面超过一整屏了，原来的尺寸是对的，把硬盘信息融到主机那一长条」。**别再靠目测** ——
本轮用 Chrome 注入探针量真实 rect（`_probe*.html`，把 JSON 写进 `<title>` 再 `--dump-dom` 抓）：

| 版本 | body 高度（1920x1065 窗口 / vh 967） |
|---|---|
| v36（机主认可的尺寸） | **1446** |
| v37（独立存储卡） | 1678（+232，超屏就来自这里） |
| v37d（本轮） | **1446**（与 v36 逐像素相同） |

做法与依据：
- 主机卡内部实测 `left 806x(162+115)` / `right 967x292`：**右栏只有走势图，竖向本来就有余量**。
- 于是存储条压进右栏、走势图吸收高度差（`svg` 292 -> 166 仍可读），卡片高度不变 => 整页不变。
  这比"缩字号/缩图表"稳妥：高度由**结构**决定，不靠像素微调。
- 顺带修两处：① 瓦片列数钉死 `repeat(4)`（`auto-fit + minmax(86px,1fr)` 在 806px 下会排成 7+1，
  实测如此，且列数随窗口漂）；② 磁盘读写瓦片改用自适应单位（模型加载时 1.7 GiB/s 曾显示成
  `1750896.0 KiB/s`，与存储条的 `1707.6 MiB/s` 撞车）。
- [!] 行尾陷阱：v37d 用 Python 切片插入的 JS 段是 **LF**，整文件变混行尾（2459 CRLF + 112 LF）。
  之后按 CRLF 写的 old 串匹配不到，`assert count==1` 直接报 0 —— **改前先归一化行尾**。
- [!] 验证方式：`window-size` 要减去浏览器 UI（1620x1080 窗口 -> vh 967），否则测出来的
  "是否超屏"永远对不上机主的观感。多宽度复核 1600/1920/2560 分别为 1446 / 1446 / 1342。
