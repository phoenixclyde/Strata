## 投机窗口策略结清（P194）与一个必须更正的判断（P195）

上游复查：仍 **v0.2.8**（`src` 最新提交 `b119f40f` 在 tag 内，releases 最高 v0.2.8），无新版本可升。

### 测了什么
投机窗口是唯一"把一个窗口的固定成本摊到更多 token"的乘数。8 臂 / 6 配置，每组 3 条 512-token 贪心，
判据 `tokens/窗口 ÷ ms/窗口`。每条臂都带 `STRATA_DECODE_TIMING=1` + `STRATA_SPEC_DEPTH=1`。

| 臂 | spec/minp | T | tok/win | ms/win | tok/s |
|---|---|---|---|---|---|
| ta 生产 | 4 / 0.70 | 2.18 | 1.79 | 39.44 | **47.05** |
| ta2 / ta3 | 4 / 0.70 | 2.21 / 2.06 | 1.79 / 1.71 | 38.69 / 37.86 | 46.27 / 45.71 |
| tf | 8 / 0.70 | 2.32 | 1.84 | 39.39 | 44.97 |
| tg | 8 / **0.50** | 3.35 | 2.03 | 50.80 | **39.96（−15.1%）** |
| th | 8 / 0.50 + `SPEC_COST` | 2.28 | 1.79 | 37.50 | 46.03 |
| tk | 8 / **0.85** | 1.79 | 1.63 | 35.24 | 47.01 |
| tl | 8 / **0.90** | 1.64 | 1.51 | 33.76 | 45.66 |

- 上限 4→8 是 **空操作**（门槛先截断）；放松门槛明确亏（专家并集 19.9→31.4/层-窗口，新增行接受率只 62%）；
  收紧门槛无收益；**引擎自己的成本规则把 T 收到 2.28，与基线重合 = 独立验证最优点**。
- ⇒ **T ∈ [1.6, 2.4] 是平地（45.7–47.1），生产在正中；T>3 是悬崖。** 不改任何参数。

### 必须更正的判断（P195）
之前用 `GPU-reach wait 28.0/38.2 = 77%` 说"GPU 四分之三时间在等专家数据"。**错了。**
那是**宿主机在等 GPU 里程碑**（host 空转）。逐 kernel 分解（`verify.cpp:2487-2488` 标签表，合计 44.98 ms/窗口）：

| 组成 | ms/窗口 | 占比 |
|---|---|---|
| 专家 VRAM 读取（`VRAM hits`） | 10.51 | **23.4%** |
| 两条 dense MLP（`hc0/hc1` norm+down+up） | 7.46 | 16.6% |
| GDN 主体（q8 gemv 2.44 / z 1.55 / out-proj 1.62 / rec 0.67 / ab 0.52 / conv 0.21） | 7.01 | 15.6% |
| 各类等待（waitA/B、PCIe grp、waitCPU、copy+combine、gap） | 6.50 | 14.5% |
| QSA 主体（q+q-idx 1.67 / attention 1.78 / scores+topk 0.89 / out-proj 0.60 / kv 0.83） | 5.88 | 13.1% |
| 路由（`router+plan+bell`） | 3.84 | 8.5% |
| shared expert + 量化 | 2.04 | 4.5% |
| head | 1.73 | 3.8% |

**最大单项 23.4%** ⇒ 任何单项开关都只值 ±1.5%。这才是历史上"每个优化都 ±1.5%"的真正原因：
**分母分散，不是被等待淹没。** 判这类开关前先看这张表，别先假设有巨大主项。

### 工具与坑
- `STRATA_SPEC_TRACE` 与 `STRATA_SPEC_DEPTH` **只在 CLI 生成路径实现**（generate.cpp:18112+），**serve 路径不产出 trace 文件**；
  serve 只有 `spec depth` 与 `decode timing` 两行。
- **引擎 stderr 不进 `docker logs`**，写在配置的 `log` 字段（我们的生产配置 = `/data/strata-huihui-ud-iq4_xs.log`）。
  arm 脚本要按 arm 切片：记 `wc -l` 起始行，结束时 `tail -n +N` 落盘。配置/日志路径要做 `/data/ → $DATA/` 映射。
- `decode timing` 行**不是**请求结束就打，实测在臂结束前后才落到日志里；解析用位置分组（每臂 4 行：warm + p0/p1/p2）。
- 平台已在上游最新；`--spec 8` 合法（`kVerifyNarrowT=8`），宽构建只是让 `--batch` 能用 16 行。
